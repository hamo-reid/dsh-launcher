# DSH Launcher v0.3.0-beta1

> 本版跨度较大：合并了 Profile 工作区重做、Plugins 分类/更新/维护、以及设置持久层的企业级重构。建议升级前备份 `~/dsh-launcher`。

### 中文版

#### ✨ 新功能 · Plugins

- **两轴分类**：每个插件按「角色」(`kind`：内置模板 / Bundle 层 / 依赖 / 仅存档) 与「管理来源」(`provenance`：插件库 / 官方内置 / 聚合子包 / 本地链接 / 外部) 两个维度分类，并**展示全部来源标签**，内置项不再是一团模糊的"内置"。
- **插件更新**：
  - npm 来源按 registry 的 `latest`（dist-tag）比对，带 TTL 缓存；
  - GitHub 来源解析仓库后查 Tags（取最高 semver），其余来源标记为「手动」；
  - 在**某个 profile** 上一键应用更新（先确保目标版本入库，再重指依赖），**运行中的 profile 拒绝更新**。
- **市场注解**：社区目录的「分类 / 已弃用」注入总览；已弃用插件可**一键迁移到替代插件**（为所有使用它的 profile 安装替代并解绑旧的，运行中拒绝）。
- **未使用版本 GC**：按插件清理未被任何 profile 使用的归档版本（保留最新与在用版本）。

#### ✨ 新功能 · Profile 工作区

- **三栏工作区**（导航 / 内容 / 检查器）：组合校验、insert 冲突列表、缺失与未激活 bundle 一目了然。
- **源码编辑**：Monaco 就地编辑 `cordis.patch.yml`，以及原始 `package.json` 与 home patch 编辑（保存前校验）。
- **配置编辑**：依赖与清单元数据（显示名、`patchReload`）就地修改；从工作区**激活已安装的 bundle 层**。
- **profile 管理**：目录改名（运行中拒绝）、在 profile 间**复制/移动 patch 层**。
- **多运行时**：同一 `(dsh, profile)` 仅允许一个实例、不同 profile 可并行；每个 profile 保存启动模式与参数；内嵌终端控制台 + 托盘运行状态。

#### 🎨 体验 / 界面

- Plugins 总览由宽表格改为**响应式卡片网格**：多条件筛选（**同维度 OR、跨维度 AND**）并**本地记忆**（localStorage），本地分页、按名称/大小/版本数/使用数排序（含升/降序）。
- 抽出共享 `Toolbar` / `FilterChips` / `SearchInput`，插件总览 / 下载中心 / 市场三页统一为「页头动作 + 工具栏 + 活动筛选 chips + 骨架/空态」的一致语言。
- Profile 页统一为 flat white 皮肤。

#### 🐛 修复 / 可靠性 · 设置持久层重构

- **原子读改写**：新增 `updateSettings/patchSettings`，所有写入统一走它们；**修复 `dsh:update` 在更新期间覆盖并发新增/改名的 dsh（lost update）**。
- **schema 版本 + 有序迁移**：旧版本读新版库不会降级写坏。
- **分键存储**：`prefs / dsh / launch / meta` 四行独立；旧的单行 `app` 首次打开自动拆分（保留原行作备份），改动只重写对应行。
- **损坏自愈**：某行解析失败会**归档**该行并按缺失处理；整库不可读时按 `主文件 → app.sqlite.bak → 空` 回退，`.bak` 每次成功落盘后镜像，归档文件保留最近 3 份。
- **崩溃安全落盘**：临时文件 `fsync` 后原子 rename；同 tick 写合并 + 无变化去重 + 退出时强制 flush。
- **设置导出/导入**（设置页「数据与备份」）：带 schema 门禁，可备份/迁移/排障。

#### 🏗️ 工程

- 测试：新增分类/更新探测、store 来源 sidecar、设置持久化（原子合并、分键往返、旧格式拆分、损坏归档、备份恢复、导出/导入、合并落盘、lost-update 回归）等用例；并清理了一批冗余/同义用例。
- 无新增运行时依赖。

### English

> This is a large release: it merges the Profile workspace rework, Plugins classification/update/maintenance, and an enterprise-grade rewrite of the settings layer. Back up `~/dsh-launcher` before upgrading.

#### ✨ Features · Plugins

- **Two-axis classification**: every plugin is classified by **role** (`kind`: built-in template / bundle layer / dependency / store-only) and by **management source** (`provenance`: store / official / sub-bundle / local-link / external), with **all source tags shown** — "built-in" is no longer an opaque bucket.
- **Plugin updates**:
  - npm-backed plugins compare against the registry `latest` (dist-tag), with a TTL cache;
  - github-backed plugins resolve their repo and check GitHub tags (highest semver); other origins are marked "manual";
  - apply updates **per profile** (ensure the target version is archived, then re-point the dependency); a **running profile is refused**.
- **Market annotations**: catalog category / deprecation are injected into the overview; a deprecated plugin can be **migrated to its replacement in one click** (install the replacement into every using profile, then detach the old one; refused while running).
- **Unused-version GC**: per plugin, remove archived versions no profile uses (keeping the newest and in-use ones).

#### ✨ Features · Profile workspace

- **Three-pane workspace** (nav / content / inspector): composition validation, insert-conflict list, missing and unclaimed bundles at a glance.
- **Source editing**: edit `cordis.patch.yml` in Monaco, plus raw `package.json` and the home patch (validated before save).
- **Config editing**: edit dependencies and manifest metadata (display name, `patchReload`) in place; **activate an installed bundle layer** from the workspace.
- **Profile management**: rename the directory (refused while running), **copy/move a patch layer** between profiles.
- **Multiple runtimes**: one instance per `(dsh, profile)`, different profiles run in parallel; per-profile saved mode and parameters; embedded console + tray run status.

#### 🎨 UX / UI

- The Plugins overview is now a **responsive card grid**: multi-condition filters (**OR within a dimension, AND across**) that are **remembered locally** (localStorage), local pagination, and sorting by name / size / versions / usage (with asc/desc).
- Shared `Toolbar` / `FilterChips` / `SearchInput` extracted; the plugins overview, download center and market now share one consistent "page actions + toolbar + active-filter chips + skeleton/empty" language.
- The Profile surface is unified to the flat white skin.

#### 🐛 Fixes / Reliability · settings rewrite

- **Atomic read-modify-write**: new `updateSettings/patchSettings` are the single write path; **fixes `dsh:update` clobbering a concurrently added/renamed dsh (lost update)**.
- **Schema version + ordered migrations**: an older build never downgrades a newer database.
- **Split rows**: `prefs / dsh / launch / meta` are independent; a legacy single `app` row is split on first open (kept as a backup), and a change rewrites only its row.
- **Corruption self-heal**: a row that fails to parse is **archived** and treated as absent; an unreadable database falls back `primary → app.sqlite.bak → empty`, `.bak` is mirrored after every successful flush, and archives are pruned to the newest 3.
- **Crash-safe flush**: temp file + `fsync` + atomic rename; same-tick coalescing with no-op dedupe and a quit-time forced flush.
- **Settings export/import** (Settings → "Data & backup"): schema-gated, for backup / migration / troubleshooting.

#### 🏗️ Engineering

- Tests: added coverage for classification/update detection, the store source sidecar, and settings persistence (atomic merge, split round-trip, legacy split, corruption archival, backup recovery, export/import, coalesced flush, lost-update regression); removed a set of redundant/tautological cases.
- No new runtime dependencies.
