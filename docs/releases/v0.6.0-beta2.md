# DSH Launcher v0.6.0-beta2

> 本版把 skill 那条轨道的**根与归属**修对了：可写根不再是写死的一条路径，而是跟着 `skill-filesystem` 的 config 行走；provider 行不再只读第一行；一处"新建成功、刷新后消失"的旧账一并清掉。同时补上**从文件夹导入**（与 ZIP 同一套规则），并把**原生对话框**的文案接进界面语言——英文界面不再弹中文文件选择框。

### 中文版

#### ⚠️ 兼容性

- **可写根改成跟随 config 行**：`skill-filesystem` 行写了 `dshHome` 时，新建 / 导入 / 库安装从此落在那个 home 下的 `skills/`，与页面显示的可写根一致。此前它们固定写 `<DSH_HOME>/skills`，与清单不一致——那样写进去的 skill 本来就没被 dsh 扫到，因此不会自动搬家。
- **行里关掉默认根（`includeDefaultRoots: false`）时没有可写根**：此时新建 / 导入 / 库安装明确拒绝（`ext.skillNoWritableRoot`），面板上的三个入口直接禁用并就地说明原因，而不是收集完输入再失败。
- **启动面板不再接受 `DSH_AGENTS_HOME` / `DSH_BUNDLED_SKILL_DIR`**：这两个变量此前只对子进程生效，而技能页读的是启动器自己的进程环境，等于两套答案。要移根请改 config 行（`agentsHome` / `bundledSkillDir`），两边都读它。
- 设置 schema 仍是 v6，本版没有新的迁移；从 beta1 升级不涉及数据结构变化。

#### ✨ 新功能 · 从文件夹导入 skill

- **两个落点同一套规则**：Skill 库与某台 dsh 的可写根各有「从文件夹导入」，与 ZIP 导入共用查重、按 frontmatter 名落盘、all-or-nothing 与失败回滚。
- **文件夹自己决定形状**：目录自带 `SKILL.md` → 整个目录是一个 bundle（其余文件是它的资源）；否则看**直接子目录**里带 `SKILL.md` 的，每个是一个 skill。**只下探一层** —— ZIP 需要任意深度是为了兼容 `repo-main/` 包装层，文件夹没有这层包装，而任意深度会把 `node_modules/` 里别人的 `SKILL.md` 一起扫进来。
- **落盘是复制，不是链接**：源目录保持自己的生命。要让 dsh 直接扫某个目录，那是 `customSkillDirs`，是另一件事。
- **一个只有文件夹才有的边界**：目标落在源目录**之内**（例如把库根自己导回库）会在落盘前被拒绝，否则 `cpSync` 会自我嵌套到路径超长。
- **入口合并成一个「导入」按钮 + 两项**（从 ZIP / 从文件夹），与「打开」同为「一个动作、两个去处」的形态。

#### 🐛 Bug 修复

- **可写根与配置脱钩**（本版修复）：清单按 `dshHome` 算、写入按 `DSH_HOME` 算，两边不一致时新建会"成功"但刷新后消失，库总览则永远显示未安装。
- **只读第一行 provider**（本版修复）：宿主是每行注册一个 provider，N 行的根应当相加；只读第一行会让其余行声明的目录整体消失，页面上没有任何"少读了一个根"的线索。现在 home 层每一行都读，带 profile 时也读该 profile 自己的行。
- **同一目录被重复列出**（本版修复）：两行声明同一目录时只列一次。
- **`DSH_BUNDLED_SKILL_DIR` 的生效条件不对**（本版修复）：宿主只在该行保留默认根时读这个变量，启动器此前无条件读，会报出一个 dsh 并不扫的 `bundled` 根。
- **「读不出」的副本却给「重新安装」**（本版修复）：读不出不是"落后"，那个按钮现在写「仍要重装」，与安装弹窗一致。
- **没有可写根时入口照样能点**（本版修复）：现在禁用并在原位说明原因，卡片也不再提供注定失败的重新安装。
- **英文界面弹中文文件选择框**（本版修复）：原生对话框由主进程绘制，拿不到渲染层的 i18n；11 个对话框的标题与文件类型标签改由一张表按已保存的界面语言取词。

#### ⚡️ 优化

- **库总览的扫描成本**：每台 dsh 从"每条库条目扫一次"变成"扫一次建索引"，成本从「条目 × dsh」降到「条目 + dsh」。
- **根标签保持唯一**：多行 provider 下 `root` 标签按根去重（页面的 React key 就是它）。
- **原生对话框文案只有一个来源**：标题与它的文件类型标签来自同一条记录，一个对话框不会只翻一半。

#### 🔧 工程 / 架构

- **新增 `core/skills/folder.ts`**，并从 `zip.ts` 抽出共用的两趟安装（`parseSkillDirs` + `installCandidates`）：两种来源一套查重与回滚，不再各写一份。
- **新增 `core/shared/dialog-text.ts`**：12 个对话框 key、中英各一份；`docs/ui-guidelines.md` §7 新增"原生对话框的文案也是界面文案"及其唯一例外（标题由调用页面命名的目录选择）。
- **规格同步**：`docs/specs/extensions.md` §3.1（多行 provider、可写根判据）、§3.3（文件夹导入）、§3.4（批量扫描）、§5（测试锚点）。
- 测试规模：111 个测试文件，1471 通过 / 1 跳过；`pnpm typecheck` / `pnpm test` / `pnpm run build` 三道门禁全绿。

### English

> This release fixes the skill track's **roots and ownership**: the writable root is no longer a hardcoded path but follows the `skill-filesystem` config row, every provider row is read instead of only the first, and an old "create succeeds, then vanishes" account is settled. It also adds **importing from a folder** (the same rules as a ZIP) and wires the **native dialogs** to the UI language — an English UI no longer pops Chinese file pickers.

#### ⚠️ Compatibility

- **The writable root follows the config row**: when the `skill-filesystem` row sets `dshHome`, creating, importing and installing land under that home's `skills/`, which is what the page already claimed. They used to write `<DSH_HOME>/skills` regardless, disagreeing with the listing — skills written that way were never scanned by dsh, so nothing is moved.
- **A row that drops the default roots (`includeDefaultRoots: false`) has no writable root**: creating, importing and installing are refused with `ext.skillNoWritableRoot`, and the panel disables the three entrances with the reason in place instead of collecting input and then failing.
- **The launch panel no longer accepts `DSH_AGENTS_HOME` / `DSH_BUNDLED_SKILL_DIR`**: those variables only ever reached the child process, while the skills page reads the launcher's own environment — two answers to one question. To move a root, change the config row (`agentsHome` / `bundledSkillDir`), which both sides read.
- The settings schema stays at v6; this release adds no migration, and upgrading from beta1 changes no data.

#### ✨ New · Importing a skill folder

- **One set of rules for both destinations**: the skill library and a dsh's writable root each offer "import from a folder", sharing the collision checks, the frontmatter name, all-or-nothing and rollback with the ZIP path.
- **The folder decides its own shape**: a `SKILL.md` at its root makes the whole folder one bundle (everything else is that skill's resources); otherwise its **direct subdirectories** holding one are the skills. **One level deep** — a ZIP needs arbitrary depth to survive a `repo-main/` wrapper, a folder has no wrapper, and walking deeper sweeps in every `SKILL.md` of every vendored `node_modules/`.
- **What lands is a copy, never a link**: the source keeps its own life. Pointing dsh at a directory is `customSkillDirs` — a different feature.
- **One hazard only a folder has**: a destination inside its own source (importing the library root back into the library) is refused before anything moves, because `cpSync` would nest the copy inside itself until the path gets too long.
- **The entrance is one "Import" button with two items** (ZIP / folder), the same shape "Open" already uses for two destinations.

#### 🐛 Fixes

- **The writable root was decoupled from the config** (fixed in this release): the listing followed `dshHome`, the writers followed `DSH_HOME`, and a mismatch made a create "succeed" and then disappear while the library overview reported not-installed forever.
- **Only the first provider row was read** (fixed in this release): the host registers one provider per row, so their roots add up; reading the first one made every other row's directories vanish with nothing on the page saying a root was missing. Every home row is read now, plus the selected profile's own rows.
- **One directory was listed twice** (fixed in this release): two rows naming the same directory are one root.
- **`DSH_BUNDLED_SKILL_DIR` applied under the wrong condition** (fixed in this release): the host reads it only while that row keeps the default roots on, and the launcher read it unconditionally — reporting a `bundled` root dsh does not scan.
- **An unreadable copy was offered a plain "reinstall"** (fixed in this release): unreadable is not "behind", so the action says "reinstall anyway" now, matching the install dialog.
- **The authoring entrances stayed clickable with nowhere to write** (fixed in this release): they are disabled with the reason in place, and a card no longer offers a reinstall that cannot succeed.
- **An English UI popped Chinese file pickers** (fixed in this release): a native dialog is drawn by the main process, which has no i18n bundle; the titles and file-type labels of all 11 dialogs now come from one table keyed by the saved UI language.

#### ⚡️ Improvements

- **The library overview's scan cost**: each dsh is indexed once instead of once per library entry, so one page costs entries + dsh instead of their product.
- **Root labels stay unique**: with several provider rows, `root` is deduplicated per root — it is the page's React key.
- **One source for native dialog copy**: a title and its file-type label come from the same entry, so a dialog cannot end up half translated.

#### 🔧 Engineering

- **New `core/skills/folder.ts`**, and the two-pass install (`parseSkillDirs` + `installCandidates`) is extracted from `zip.ts`: both sources share one implementation of the collision rules and the rollback instead of growing a second.
- **New `core/shared/dialog-text.ts`**: twelve dialog keys, Chinese and English; `docs/ui-guidelines.md` §7 now states that native dialog copy is UI copy, with its one exception (a folder picker whose title the calling page names).
- **The spec follows the code**: `docs/specs/extensions.md` §3.1 (several provider rows, the writable-root predicate), §3.3 (folder import), §3.4 (the batch scan), §5 (test anchors).
- Test scale: 111 test files, 1471 passing / 1 skipped; `pnpm typecheck`, `pnpm test` and `pnpm run build` are green.
