# DSH Launcher v0.6.0-beta4

> 本版回答一个此前没人回答的问题：**这个 dsh 到底占了多少硬盘**。DSH 页原本能说清一个安装在哪，却说不出它有多重——而真正堆数据的地方是 home（sessions、attachments、每个 profile 的 node_modules）。顺带做了两件事：home 可以逐层看进 去，两个「从库安装」弹窗终于能搜索和翻页。

### 中文版

#### ⚠️ 兼容性

- **安装路径的显示变了**：DSH 页「基本信息」的`所在路径`与它的「打开目录」，现在都指向 `dsh/versions/<版本>`，不再是 `node_modules/@deepseek-ai/dsh`。**没有任何文件被移动**——只是不再把一个没人管理的内部路径当作"安装位置"展示；两者共用同一个取值，显示的和打开的不会分叉。
- **磁盘统计只读**：整个功能只 `readdir` + `stat`，没有删除入口，也不写任何文件；`打开目录` 只接受**目录**（文件会被拒绝——把 `node_modules/.bin` 下的 `.cmd` 交给系统处理器等于执行它）。
- **只统计托管安装**：系统级 / 手动添加的 dsh 共用 `~/.dsh`，那是宿主自己的数据，不在统计范围；面板会直接说明而不是显示一堆 0。

#### ✨ 新功能

- **DSH home 磁盘占用**：选中哪个 dsh 就统计哪个的 home。三档口径——**可回收**（所有硬链接都在该 home 内，删掉真能腾出的量）、**逻辑大小**（资源管理器会显示的那个数）、以及其中**与 dsh 本体 / 插件库共享**的部分。为什么必须分开：pnpm 把同一个包体硬链接进插件库、dsh 本体和每个 profile，实测这些文件里 **88% 的 nlink > 1**，直接相加会把一份字节算成很多份。
- **列表 / 环形图切换**：环形图悬停时弧段弹出、中心读数跟着切换为该目录的名称与体积，图例同步高亮并显示占比；入场有动效，系统开了「减少动态效果」时自动关闭。
- **结构浏览器**：逐层进入 home，每层按体积排序，列出体积 / 文件数与占比；**一层一次测量**，深树只为实际打开的层付费，返回上级走本次会话内的缓存。`node_modules` 那类行标注为「插件库硬链接」，不冒充 home 自己的字节。
- **「从库安装」支持搜索与翻页**：技能库与 MCP 库的弹窗现在可按名称 / 描述 / 地址搜索，每页 8 条并显示总数；技能可「隐藏已是最新的」、MCP 可「隐藏已添加的」，筛选与行的可点状态共用同一条判定，不会出现"藏了能点的行"。

#### ⚡️ 优化

- **按 home 逐个测量**：一次 IPC 只测一个 home，结果边测边显示。此前一次性测完全部 home 会让主进程连续阻塞数秒、界面只有一个转圈。
- **`打开目录` 移到「目录配置」**：和它打开的那个路径放在一起；磁盘面板只保留「浏览结构」，同一屏不再有两个同义按钮。
- **文案收紧**：面板去掉了副标题、空态的长解释与「当前」角标，两条注释合并成一行；空态只留一句「点「开始统计」查看占用」。

#### 🔧 工程 / 架构

- **新增依赖 `chart.js` + `react-chartjs-2`**（唯一传递依赖是 `@kurkle/color`），并拆进独立的 `vendor-charts` chunk（258 kB，随 DSH 页懒加载）。先试过 recharts：它把 redux-toolkit / immer / 整个 `victory-vendor` d3 拖进 DSH chunk，70 kB → **824 kB**，因此放弃。
- **硬链接口径的单一实现**：`core/dsh/home-usage.ts` 按 `${dev}:${ino}:${size}` 去重，`nlink` 等于本 home 内出现次数才算"可回收"；跨顶层条目的硬链接由 home 级的合并表折算，不再把各条目相加（那样会漏掉"删掉整个 home 才释放"的字节）。
- **新增模块**：`core/dsh/home-usage.ts`（测量 + 路径守卫 `resolveInHome`）、`ipc/dsh/home-usage.ts`（`home:targets` / `home:scan` / `home:browse` / `home:reveal`）、`renderer/lib/libraryPick.ts`（搜索与分页算术）、`renderer/views/dsh/{HomeUsagePanel,HomeUsagePie,HomeBrowseModal}.tsx`。
- **文档**：`docs/ui-guidelines.md` 补了图表配色约定（分类色板用 antd 预设色 token，刻意不复用语义色）；README 中英各补一条功能说明。
- 测试规模：121 个测试文件，1584 通过 / 1 跳过；`pnpm typecheck` / `pnpm test` / `pnpm test:coverage` / `pnpm run build` 四道门禁全绿（覆盖率 lines 91.57% / branches 83.43% / functions 95.67%）。

### English

> This release answers a question nothing in the app answered: **how much disk does this dsh actually take**. The DSH page could say where an install lives, but not what it weighs — and the weight is in the home (sessions, attachments, every profile's node_modules). Two accompaniments: the home can now be walked level by level, and both "pick from the library" dialogs finally support search and paging.

#### ⚠️ Compatibility

- **The install path shown has changed**: `Location` on the DSH page and its reveal button now point at `dsh/versions/<slot>` instead of `node_modules/@deepseek-ai/dsh`. **No file moved** — the page simply stopped presenting an internal path nobody manages as "where the install is"; both read one value, so the path on screen and the folder opened cannot drift apart.
- **Disk usage is read-only**: the feature only ever calls `readdir` and `stat`. There is no delete channel and nothing is written; `Open folder` accepts a **directory** only (a file is refused — handing a `.cmd` shim from `node_modules/.bin` to the OS handler would execute it).
- **Managed installs only**: a system / manually added dsh shares `~/.dsh` with the host, which is the host's data, not a launcher cost. The panel says so instead of showing a row of zeros.

#### ✨ New

- **Home disk usage**: the selected dsh's home, measured. Three numbers that are not interchangeable — **reclaimable** (every hard link lives inside that home, so deleting it frees them), **apparent** (what a file explorer shows), and the part **shared** with the dsh install / plugin store. They have to be separate: pnpm hard-links one package body into the store, the install and every profile, and on a real machine **88% of these files carry nlink > 1**, so a plain sum counts one body many times.
- **List / donut switch**: hovering a slice lifts it out and swaps the centre readout to that folder's name and size, with the legend highlighting in step and showing each share. The donut animates in, and stays still when the OS asks for reduced motion.
- **Structure browser**: walk the home one level at a time, largest first, with size, file count and share per row. **One level per measurement** — a deep tree costs only the levels actually opened, and going back up is served from the session's cache. `node_modules` rows are tagged as the plugin store's bytes rather than passed off as the home's own.
- **Search and paging in the library pickers**: the skills and MCP dialogs now filter by name / description / address, show 8 rows per page with the real total, and offer "hide up-to-date" (skills) / "hide already added" (MCP). The toggle reuses the same predicate as the rows' disabled state, so a filter can never hide a clickable row.

#### ⚡️ Improvements

- **One home per measurement**: each `home:scan` call measures a single home, so results appear as they land. Measuring every home in one request blocked the main process for seconds behind a single spinner.
- **`Open folder` moved into Directory config**: next to the path it opens. The usage panel keeps only "Browse files" — one screen no longer carries two buttons for the same gesture.
- **Tighter copy**: the panel dropped its subtitle, its long empty-state explanation and the "Current" badge, and folded two notes into one line; the empty state is now a single sentence.

#### 🔧 Engineering

- **New dependencies `chart.js` + `react-chartjs-2`** (one transitive dependency, `@kurkle/color`), split into their own `vendor-charts` chunk (258 kB, loaded with the DSH page). Recharts was tried first and rejected: it dragged redux-toolkit, immer and the whole `victory-vendor` d3 set into the DSH chunk — 70 kB → **824 kB**.
- **One implementation of the hard-link arithmetic**: `core/dsh/home-usage.ts` dedupes by `${dev}:${ino}:${size}` and calls bytes "reclaimable" only when `nlink` equals the occurrences inside that home; links that span top-level entries are folded through a home-wide map instead of adding the per-entry numbers (which would lose the bytes only the whole home frees).
- **New modules**: `core/dsh/home-usage.ts` (measurement + the `resolveInHome` path guard), `ipc/dsh/home-usage.ts` (`home:targets` / `home:scan` / `home:browse` / `home:reveal`), `renderer/lib/libraryPick.ts` (search and paging arithmetic), `renderer/views/dsh/{HomeUsagePanel,HomeUsagePie,HomeBrowseModal}.tsx`.
- **Docs**: `docs/ui-guidelines.md` gained the chart colour rule (categorical slices use antd's preset colour tokens, deliberately not the semantic ones); both READMEs gained a feature bullet.
- Test suite: 121 files, 1584 passing / 1 skipped; `pnpm typecheck`, `pnpm test`, `pnpm test:coverage` and `pnpm run build` all green (coverage lines 91.57% / branches 83.43% / functions 95.67%).
