# DSH Launcher v0.6.0-beta3

> 本版修的是**隔离**：同时跑两个 profile 时，在其中一个页面上的改动会让**另一个进程**重载——根因是 home 层补丁机器级共享，而界面从没把这件事说出来。顺着这条线还修掉同源的一批账：运行中改 profile 会让归档"删一半"、dev 链接与插件库对同一个动作给出两种回答、克隆出的 profile 继承源的操作日志。发版前做了一次全项目死代码清理。

### 中文版

#### ⚠️ 兼容性

- **写 home 层会先问一句**：`<home>/cordis.patch.yml` 由该 home 下**所有** profile 组合，且每个运行中的进程都在监听它——文件不存在时也在监听范围内，所以**第一次写入（哪怕内容只是 `[]`）就会触发重载**。这以前是静默生效的；现在只要有 profile 在跑就弹确认，层栈里该层也标成「共享层」。
- **运行中改 profile 会被拦下**：装插件、卸载、删除版本并断开引用、链接 / 修复 dev 包，都会在**任何写盘之前**回答"这些 profile 正在运行"，并给出**停止后继续**。此前只有「应用更新」和「dev 链接」有守卫，插件库这边的四个入口没有。
- **删除归档不再可能"半删"**：先把版本移出 `archive/`（进 `.trash`）再删字节。移动本身被拒时归档**原样保留**并报 `store.fileLocked`，同时点名正在占用它的 profile。
- **克隆是独立个体**：不再复制 `.plugin-manager/`（源的操作日志）、`.dsh-launcher-id`、`*.bak`，并把 `dsh-profile-<源名>` 改写为新名字；手写过的清单名不动。
- **`patchReload` 照旧写进清单，但是否生效取决于所启动的 dsh 版本**：不实现该字段的版本（如 `official-0.2.0-rc1`，实测零命中）一律热重载 patch。设置页已就地说明，免得它看起来像个关不掉的开关。

#### 🐛 Bug 修复

- **一个 profile 的改动触发另一个进程重载**（本版修复）：在 A 的页面里动了 home 层的行 / 保存了 home 分节 / 把 MCP 行写到 home 层，都会让该 home 下**所有**在跑的 profile 立刻重新组合。界面从未提示这一层是机器级的。
- **运行中写 profile 没有守卫**（本版修复）：安装、卸载、断开、删除版本会在 live 进程下改写清单并跑 pnpm；Windows 上删到被占用的原生模块就 EPERM。现在四条路径与更新/dev 链接口径一致。
- **删除失败留下半个归档**（本版修复）：EPERM 中断在清单已改之后，结果是"库里没有、盘上删了一半"，界面只报 internal error。现在改为先移出命名空间再删字节，最坏只留可回收的残骸。
- **`store.fileLocked` 点不到人**（本版修复）：提示里的"谁在占用"是在清单已经 detached 之后重新扫描的，因此永远是空。
- **克隆继承源的身份**（本版修复）：复制来的 `.plugin-manager/` 让新 profile 带着旧的操作日志，清单名也相同——两个 profile 在诊断里互相冒充。
- **启动被归档清理阻塞**（本版修复）：清理同步跑在 `createWindow` 之前，一个 stash 里躺着整份插件就会白屏等待。现在挪到窗口创建之后。
- **dev 链接与插件库对同一动作两种回答**（本版修复）：同一件"往 profile 里装东西"，插件库问一句并给「停止后继续」，dev 链接直接拒绝。现在一致。
- **`store:migrate` 不看运行状态**（本版修复）：它会把 profile 清单里指向旧布局的路径重写掉，运行中的进程仍在读旧路径。
- **迁移替代品可能问错进程**（本版修复）：用 `name → id` 映射判断谁在跑，两个 dsh 条目显示名相同时只会问其中一个。改用 usage 自带的 `dshId`。
- **四处渲染层死状态**（本版修复）：市场页的自定义 catalog 地址/令牌、官方安装弹窗的 `error`、下载版本弹窗的 `installing`、设置页的 `reloadMarket` —— 全是界面已经不用的残留，其中`installing` 接着 `confirmLoading`，让按钮永远不转。

#### ✨ 新功能

- **运行中确认框三选一**：取消 / 仍然继续 / **停止后继续**。选后者会先通过 `run:stopProfile`（按 `(dsh, profile)` 定位，不需要 run id）停掉相关进程，再重试写入——这是唯一能让改动真正生效的路径。
- **dev 插件卡片上的「运行中」标签**：源码目录正被某个 profile 的 live 进程使用时标出来，并说明构建 / 装依赖 / 改源码不会进入运行中的进程。
- **层栈的共享层标记**：home 层的行旁常驻告警，说明它写的是机器级文件、作用于本 dsh 下所有 profile。

#### ⚡️ 优化

- **删除改为两步**：先 rename 进 `.trash`（版本立刻从枚举里消失），再尽力删字节；启动时补一次回收。
- **`deleteTreePhysical` 收失败而不是抛**：一个被占用的文件不再中断整棵树，其余部分照删，失败路径逐条上报。
- **启动清理移出启动路径**：与相邻的 `repairArchiveLinks` 一致，不阻塞窗口。

#### 🔧 工程 / 架构

- **全项目死代码清理**（发版前）：`tsc --noUnusedLocals --noUnusedParameters` 的 51 处归零；64 个没有界面引用的 i18n 键、3 个零引用导出、3 个无人抛出的错误码一并删除。另审计过依赖（36 个全部在用）、无引用文件、文档里的悬空链接、`TODO/FIXME/@deprecated` 标记——后三者结论都是"无需处理"。
- **新增模块**：`core/store/usage.ts`（"谁还在引用这个插件"的唯一判定，守卫与级联共用）、`ipc/plugins/guard.ts`（运行中拒绝的统一形状）、`ipc/profile/shared-layer.ts`（home 层披露）、`renderer/lib/pluginWrite.tsx`（三处确认框与重试）。
- **`DshContext` 补上 `id`**：名字是标签、id 才是身份，运行互斥要按 id 问。
- **`.trash` 只有一种拼法**：`storeTrashDir` + `stashLeaf` 收进 `layout.ts`，替换与删除两条路径共用。
- **文档**：`docs/TROUBLESHOOTING.md` 新增 §11「一个 profile 改了，另一个 profile 的进程重载了」——dsh 只监听三处、哪一处是共享的、本应用里哪些操作会写到它，以及另外两种会串场的情形。
- 测试规模：115 个测试文件，1505 通过 / 1 跳过；`pnpm typecheck` / `pnpm test` / `pnpm run build` 三道门禁全绿。

### English

> This release is about **isolation**: with two profiles running, a change made on one profile's page made the **other process** reload — the home patch layer is machine-level and every running process watches it, which the UI never said. Fixing that surfaced the same family of problems: editing a running profile could leave an archive half-deleted, the dev door and the plugin store answered one question two different ways, and a clone inherited its source's identity. A project-wide dead-code sweep landed before the release.

#### ⚠️ Compatibility

- **Writing the home layer now asks first**: `<home>/cordis.patch.yml` is composed into **every** profile under that home, and every running process watches it — including while it does not exist, so the **first write (a bare `[]`) is what fires**. That used to happen silently; now a running profile produces a confirmation, and the layer pane marks the layer as shared.
- **Editing a running profile is refused**: installing, uninstalling, deleting a version with detach, and linking / repairing a dev package all answer "these profiles are running" **before anything is written**, with a **stop and continue** option. Only the update path and the dev-link path had a guard before; the store's four entrances did not.
- **Deleting an archive can no longer half-delete**: the version is moved out of `archive/` (into `.trash`) before a byte is deleted. When the move itself is refused the archive is left **exactly as it was** and the answer is `store.fileLocked`, naming the profiles holding it.
- **A clone is its own profile**: it no longer carries `.plugin-manager/` (the source's operation log), `.dsh-launcher-id` or `*.bak`, and `dsh-profile-<source>` becomes the new name; a hand-written manifest name is left alone.
- **`patchReload` is still written, but whether it applies depends on the launched dsh build**: builds without the field (e.g. `official-0.2.0-rc1`, zero hits) always hot-reload the patch. The settings pane now says so, instead of looking like a switch that does nothing.

#### 🐛 Fixes

- **A change in one profile reloaded another process** (fixed): toggling a home-layer row, saving the home section, or writing an MCP row into the home layer recomposed **every** running profile under that home. Nothing on screen said the layer was machine-level.
- **No guard on writing a running profile** (fixed): install, uninstall, detach and version-delete rewrote the manifest and ran pnpm under a live process; on Windows a held native module then failed with EPERM. The four paths now match the update and dev-link behaviour.
- **A failed delete left half an archive** (fixed): the EPERM hit after the manifest had been rewritten, so the store no longer listed the plugin while the disk still held part of it, reported as an internal error. The version now leaves the namespace first and its bytes are deleted after, leaving at most a reclaimable leftover.
- **`store.fileLocked` named nobody** (fixed): the "who is holding it" hint was computed after the manifests were detached, so a fresh scan always found nothing.
- **A clone inherited its source's identity** (fixed): the copied `.plugin-manager/` made the new profile carry the old operation log, and the manifest name was identical — two profiles impersonating each other in every diagnostic.
- **Startup stalled on the archive sweep** (fixed): the sweep ran synchronously before `createWindow`, so a stash holding a whole plugin meant a blank window. It runs after the window now.
- **The dev door and the store gave two answers** (fixed): installing into a profile asked a question with a stop-and-continue option from the store, but refused outright from a dev link.
- **`store:migrate` ignored running processes** (fixed): it rewrites profile manifests onto the versioned layout while a live process still reads the old paths.
- **Migrating to a replacement could ask the wrong process** (fixed): a `name → id` map decided who was running, so two dsh entries sharing a display name asked only one of them. It uses the usage point's own `dshId`.
- **Four dead pieces of renderer state** (fixed): the market page's custom-catalog URL/token, the official-install modal's `error`, the download dialog's `installing`, and a settings `reloadMarket` — none reachable from the UI, and `installing` was wired to `confirmLoading`, so that button never spun.

#### ✨ New

- **A three-way question for running profiles**: cancel / continue anyway / **stop and continue**. The last one stops the processes via `run:stopProfile` (addressed by `(dsh, profile)`, no run id needed) and retries the write — the only path that actually makes the change take effect.
- **A "running" tag on dev plugin cards**: shown while a live profile uses that source folder, with the note that building, installing its deps or editing the source will not reach that process.
- **A shared-layer marker in the layer stack**: the home layer carries a standing warning that its file is machine-level and applies to every profile under this dsh.

#### ⚡️ Improvements

- **Deletion is two steps**: rename into `.trash` (the version leaves the enumeration immediately), then delete the bytes best-effort, with a sweep at the next start.
- **`deleteTreePhysical` collects instead of throwing**: one held file no longer abandons the rest of the tree, and every path it could not remove is reported.
- **The startup sweep is off the startup path**, matching the neighbouring `repairArchiveLinks`.

#### 🔧 Engineering

- **Project-wide dead-code sweep** (before the release): the 51 `tsc --noUnusedLocals --noUnusedParameters` findings are zero; 64 i18n keys no screen references, three unreferenced exports and three error codes nothing throws are gone. Dependencies (all 36 in use), unreferenced files, dangling doc links and `TODO/FIXME/@deprecated` markers were audited too — the last three needed no change.
- **New modules**: `core/store/usage.ts` (the single "who still references this plugin" predicate, shared by the guards and the detach cascade), `ipc/plugins/guard.ts` (one shape for a running-profile refusal), `ipc/profile/shared-layer.ts` (the home-layer disclosure), `renderer/lib/pluginWrite.tsx` (the confirmations and the retry).
- **`DshContext` carries `id`**: the name is a label, the id is the identity a run registry asks about.
- **One spelling for `.trash`**: `storeTrashDir` and `stashLeaf` live in `layout.ts` now, shared by the replace and the remove paths.
- **Docs**: `docs/TROUBLESHOOTING.md` gains §11 — the three paths dsh watches, which one is shared, which operations in this app write it, and the two other ways two profiles can move together.
- Test scale: 115 test files, 1505 passing / 1 skipped; `pnpm typecheck`, `pnpm test` and `pnpm run build` are green.
