# DSH Launcher v0.2.0-beta4

### 中文版

#### 🐛 修复
- **启动 profile 会再拉起一个启动器实例**：bundled 运行环境下 dsh 的 `process.execPath` 指向启动器自身（Electron 二进制）；此前的清理 shim 删除了 `ELECTRON_RUN_AS_NODE`，导致 dsh 内部 `fork`/`spawn` 该可执行文件时把整个启动器应用又启动了一遍（日志表现为 `run started` 后约 5 秒出现新的 `app starting` / `settings db opened` / `main window created`）。shim 现在同时为「以 Electron 二进制为子进程」的 spawn/fork 重新注入 `ELECTRON_RUN_AS_NODE=1`，这些子进程会正确以 Node 运行；dsh 启动的编辑器等（走自己的 exe）不受影响。
- **重复多开可互相覆盖 / 写坏设置**：应用此前没有单实例限制，且设置库是整文件原地覆盖写。现在主进程获取单实例锁——第二次启动会退出并聚焦已有窗口；`saveSettings` 改为「临时文件 + rename」的原子替换（目标被临时占用时回退直写），崩溃或并发写不再产生损坏的 `app.sqlite`。该单实例锁同时是上述误拉起子进程的兜底：即使补丁未覆盖的路径再次启动应用，也会立即退出，不会变成重复实例。

#### 🏗️ 工程
- 为子进程 shim 与设置原子写补充单元测试。

### English

#### 🐛 Fixes
- **Starting a profile launched a second launcher instance**: under the bundled runtime, dsh's `process.execPath` is the launcher itself (the Electron binary); the cleanup shim dropped `ELECTRON_RUN_AS_NODE`, so a `fork`/`spawn` of that executable inside dsh booted the whole launcher app again (visible as a fresh `app starting` / `settings db opened` / `main window created` about 5s after `run started`). The shim now also re-injects `ELECTRON_RUN_AS_NODE=1` for children spawned from the Electron binary, so they run as Node; editors and other by-exe children are left untouched.
- **Repeated launches could clobber or corrupt settings**: the app had no single-instance limit and flushed settings by overwriting `app.sqlite` in place. The main process now takes a single-instance lock (a second launch exits and focuses the existing window), and `saveSettings` replaces the database atomically via a temp file and rename, falling back to a direct write when the target is transiently locked. The lock doubles as a backstop for the stray dsh child: even an uncovered path now exits instead of becoming a duplicate instance.

#### 🏗️ Engineering
- Added unit tests for the child-spawn shim and the atomic settings write.
