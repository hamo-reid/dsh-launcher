# DSH Launcher v0.4.0-beta1

> 本版主线是**扩展（Extensions）分区**：MCP 服务器与 Skill 都升级为**可跨 profile 复用的启动器级库**，MCP 密钥加密落盘、连通性可实测；同时完成了一次覆盖主进程与渲染层的**架构重构**（`core/`、`ipc/` 按域分文件夹，上帝模块与上帝组件拆分）。建议升级前备份 `~/dsh-launcher`。

### 中文版

#### ✨ 新功能 · MCP 服务器

- **按层管理**：MCP 服务器可以写在**某个 profile 的 patch 层**，也可以写在**home 层**（对所有 profile 生效），界面按层分别列出并可切换；每一行可**启停**而不必删除（禁用是 id 定向的覆盖行，bundle 自带的行也能被覆盖掉）。
- **JSON 编辑模式**：表单与 JSON 两种编辑方式可切换，JSON 侧有实时校验与错误定位。
- **密钥不落明文**：MCP 的启动密钥经 `safeStorage` **加密**保存（`core/mcp/secrets.ts`），启动时注入子进程环境；patch 文件里只留 `!!js process.env.<NAME>` 引用。名称会跨进程传给渲染层，**值不会**，也不写日志、不进设置导出。
- **连通性实测**：可以对一条库内条目**真的连一次**做 `initialize` 握手（stdio 或 HTTP），把失败原因就地显示。启动器**从不调用工具**，服务器挂了也只是 `ok:false` 的探测结果，不是 IPC 错误。

#### ✨ 新功能 · Skill

- **按 dsh 的文件系统根列出**：复刻 provider 的根优先级（custom < user-dsh < user-agents < bundled），dsh 会**静默忽略**的文件（frontmatter 不合法等）会带着原因显示出来，而不是消失。
- **zip 导入**：拖入或选择 zip 即可导入，**两趟校验**（先全部解析并查重，再落盘），失败不留半个结果；带 zip-slip 防护（绝对路径、盘符、`..` 一律拒绝）。
- **只写可写的那个根**：编辑/删除发生在 `<dshHome>/skills`，删除走系统回收站（可撤销），从不碰只读根。

#### ✨ 新功能 · 启动器级库（跨 profile 复用）

- **MCP 库与 Skill 库**：两者都可以在启动器级保存一份定义，再**按需应用**到某个 profile / 某个 dsh。MCP 条目支持**一键同步**（把已应用但漂移的行改回库里的定义，保留行 id 与禁用状态；**手写过的行会被跳过并在结果里标出，绝不覆盖**）。
- **Skill 库**：内置脚手架、编辑器、删除，以及「安装到某个 dsh 的可写根」——重名时可选择覆盖。

#### ✨ 新功能 · 开发插件解析

- **解析目标可选**：诊断不再默默使用「第一个注册的 dsh」，而是显式选择一个 **宿主 + profile 链**并**记住**；patch 行与 peer 都按这条链解析。
- **按 id 或包名解析**：`dsh.bundle.patch` 的行既可能是 id 也可能是包名，两种都能解析；结果**带缓存**，链或层文件变了才重算。
- 报告会标明**这个判定是对着哪条链算出来的**，避免把缓存结果误当成新鲜的。

#### 🐛 修复

- **带 `!!js` 密钥引用的行 config 无法保存**：校验走了 `FAILSAFE_SCHEMA`，而该 schema 遇到 cordis 的 `!!js` 标签会**抛异常**，于是「在 profile 的 patch 区编辑一个 MCP 行的 config 并保存」必然报「不是合法 YAML」。现在与 patch 校验共用同一条 `!!js` 逃逸路径——**先写失败用例再修**，红转绿。
- **Skill 编辑器的实时预览会谎报**：它用 `trim` 判断 `---` 围栏，而保存路径要求围栏在第 0 列，于是**缩进的围栏预览显示「有效」、保存却被拒**。预览现在与解析器一致。
- **Profile 导航栏**：同一动作显示两次；带标签的项会换行。现在一项一动作、计数同行。
- **PATH 探测可能卡住**：`where`/`which dsh` 现在有 3 秒上限，探测不会再挂起界面。
- 本地安装面板移除了「从文件夹安装」入口（该路径已由开发插件覆盖）。

#### 🎨 体验 / 界面

- 长列表弹窗（MCP、诊断、运行输出）的滚动体放在**弹窗内部**，底部操作行不再被挤出视口。
- Skill 与 MCP 面板重建为与插件页一致的卡片/列表形态，来源与状态标签统一。

#### 🏗️ 工程 / 架构

- **`core/` 与 `ipc/` 按域分文件夹**：`core/` 63 个平铺文件收进 9 个域目录（`profile/ store/ settings/ mcp/ skills/ dsh/ patch/ github/ shared/`），`ipc/` 20 个收进 5 个；文件名里只为「平铺时消歧」而存在的前缀随之去掉（`store-install.ts` → `store/install.ts`）。共移动 132 个文件、重写 586 处模块路径。
- **上帝模块拆分**（每个都保留原入口，导入路径与既有测试零改动）：`profile`(755) `ipc/plugins`(717) `settings`(616) `dsh`(594) `mcp-probe`(578) `skills`(569) 拆为聚焦模块 + barrel/facade；`ipc/profile`(35 频道) 与 `ipc/extensions`(24 频道) 拆为按功能分组的子注册器。
- **上帝组件拆分**：`ProfileDetail.tsx` 1173 行 / 49 个 `useState` 拆为容器 + 12 个模块；插件页、弹窗集合（6 个页面）同样拆分，弹窗各自持有自己的状态。
- **纯逻辑下沉到 `renderer/src/lib/` 并补测**：格式化、层标签、筛选、步骤行、开发插件判定、skill frontmatter。**测试从 702 项 / 52 文件增至 794 项 / 64 文件**。
- **跨层重复归一**：`dshId` 窄化、静态加密信封、patch 文件名、进程树 kill、缓存簿记、manifest 读写、profiles 根/pnpm workspace/run 守卫，此前各有 2–4 份，现各自一处。
- **删除无引用代码**：7 个声明（含一个从仓库基线起就无人渲染的弹窗组件）删除，82 个只在自身文件内使用的导出收回 `export`。
- `docs/design/` 与 `TROUBLESHOOTING` 的 27 处模块路径重指向新结构；`docs/audit/` 与历史发行说明**保持原样**（它们是带日期的记录，改写等于篡改）。
- 无新增运行时依赖。

### English

> This release is about the **Extensions section**: MCP servers and Skills both become **launcher-global libraries** reusable across profiles, MCP secrets are encrypted at rest, and connectivity can be actually tested. It also lands a sweeping **architecture refactor** across the main and renderer processes (`core/` and `ipc/` regrouped into domain folders; the god modules and god components split). Back up `~/dsh-launcher` before upgrading.

#### ✨ Features · MCP servers

- **Managed per layer**: a server can live in a **profile's patch layer** or in the **home layer** (applying to every profile); the UI lists them per layer and switches between them. Any row can be **disabled** without deleting it — the override is an id-targeted row, so even a bundle-provided row can be turned off.
- **JSON edit mode**: form and JSON editing side by side, with live validation and error location on the JSON side.
- **Secrets never at rest in the clear**: launch secrets are stored **encrypted** via `safeStorage` (`core/mcp/secrets.ts`) and injected into the child's environment at launch; the patch file only ever holds a `!!js process.env.<NAME>` reference. Names cross to the renderer, **values never do** — and are never logged or exported.
- **Real connectivity probe**: a library entry can be **actually connected to** for one `initialize` handshake (stdio or HTTP), with the failure reason shown inline. The launcher **never calls tools**, and a dead server is a `ok:false` probe result, not an IPC error.

#### ✨ Features · Skills

- **Listed across the filesystem roots dsh scans**, mirroring the provider's precedence (custom < user-dsh < user-agents < bundled). Files dsh would **silently ignore** (bad frontmatter and so on) are surfaced with the reason instead of vanishing.
- **Zip import**: drop or pick an archive. Two passes — validate and collision-check everything first, then install — so a failure leaves nothing half-done. Zip-slip guarded: absolute paths, drive prefixes and `..` are refused.
- **Only the writable root is written**: edits and deletes happen in `<dshHome>/skills`, deletion goes to the OS recycle bin (reversible), and read-only roots are never touched.

#### ✨ Features · Launcher-global libraries

- **MCP and Skill libraries**: both can hold a definition at launcher level and **apply it** to a chosen profile or dsh. MCP entries have **one-click sync**, which rewrites rows that drifted back to the library's definition while preserving row ids and disabled flags — and **skips hand-written rows**, reporting them rather than overwriting.
- **Skill library**: scaffold, edit, delete, and install into a dsh's writable root, with an overwrite option on a name clash.

#### ✨ Features · Dev-plugin resolution

- **The compare target is explicit**: diagnosis no longer silently uses "the first registered dsh" — you pick a **host + profile chain**, it is **remembered**, and both patch rows and peers resolve through it.
- **Resolved by id or package name**, whichever the `dsh.bundle.patch` row carries, and **cached** — recomputed only when the chain or a layer file changes.
- Reports say **which chain they were computed against**, so a cached verdict is never mistaken for a fresh one.

#### 🐛 Fixes

- **A row config carrying a `!!js` secret reference could not be saved**: validation used `FAILSAFE_SCHEMA`, which **throws** on cordis's `!!js` tag, so editing an MCP row's config in a profile's patch area and saving always failed with "not valid YAML". It now shares the `!!js` escape the patch validator already had — written as a failing test first, then fixed.
- **The skill editor's live preview lied**: it compared each line to `---` after `trim`, while the save path requires column 0 — so an **indented fence previewed as valid and was then refused on save**. The preview now matches the parser.
- **Profile rail**: the same action appeared twice, and a labelled item wrapped. One action and one line per item now, count included.
- **The PATH probe could stall**: `where`/`which dsh` is now bounded at 3 seconds, so discovery can never hang the UI.
- The local install panel's "install from folder" entry is gone; dev plugins cover that path.

#### 🎨 UX / UI

- Long dialogs (MCP, diagnosis, run output) scroll **inside** the dialog, so the action row at the bottom can no longer be pushed out of view.
- The Skill and MCP panels were rebuilt in the same card/list shape as the plugins page, with consistent source and status tags.

#### 🏗️ Engineering / architecture

- **`core/` and `ipc/` regrouped into domain folders**: the 63 flat files in `core/` became nine domain folders (`profile/ store/ settings/ mcp/ skills/ dsh/ patch/ github/ shared/`) and the 20 in `ipc/` became five. Filename prefixes that existed only to disambiguate a flat listing are gone (`store-install.ts` → `store/install.ts`). 132 files moved, 586 module paths rewritten.
- **God modules split** — each keeping its original entry point, so import paths and every existing test are unchanged: `profile` (755), `ipc/plugins` (717), `settings` (616), `dsh` (594), `mcp-probe` (578), `skills` (569) became focused modules behind a barrel or facade; `ipc/profile` (35 channels) and `ipc/extensions` (24) became sub-registrars grouped by what they act on.
- **God components split**: `ProfileDetail.tsx` (1173 lines, 49 pieces of state) became a container plus twelve modules; the plugins page and six pages' worth of dialogs likewise, with each dialog owning its own state.
- **Pure logic lifted into `renderer/src/lib/` with tests**: formatters, layer labels, filters, step rows, dev-plugin decisions, skill frontmatter. **Tests went from 702 in 52 files to 794 in 64.**
- **Cross-layer duplicates unified**: the `dshId` narrowing, the at-rest secret envelope, the patch filename, the process-tree kill, the cache bookkeeping, manifest reading/writing, and the profiles-root / pnpm-workspace / run-guard helpers each had two to four copies and now have one.
- **Dead code removed**: seven declarations deleted (including a dialog component nothing had rendered since the repo baseline) and 82 exports that no other file referenced pulled back to module scope.
- 27 module paths in `docs/design/` and `TROUBLESHOOTING` repointed at the new structure; `docs/audit/` and past release notes were left as they are — they are dated records, and rewriting them would falsify them.
- No new runtime dependencies.
