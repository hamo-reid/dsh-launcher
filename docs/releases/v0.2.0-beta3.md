# DSH Launcher v0.2.0-beta3

### 中文版

#### 🐛 修复
- **插件库的 pnpm store 会落到硬盘根目录**：未显式指定 store 时，pnpm 会按用户主目录自算 store；一旦项目位于另一块盘，就会在该盘根目录留下一个不受管的 `.pnpm-store`。现在 runPnpm 始终注入配置好的插件库 store（启动时统一接线），profile / dsh 安装也共享同一份缓存；profile 的导入导出同步改走 pluginDir() 取值，未配置时也会落到默认目录。
- **IPC 参数可越界读写**：渲染进程传入的 profile 名称此前未校验即拼入路径，构造值可越出 profiles 目录进行读、写、改名甚至删除；profile 导入还会递归删除任意 localSource 路径。现在统一的名称守卫同时约束 IPC 与 core 的 store 路径构建：所有 profile handler 校验名称，导入临时目录清理限定在 import-tmp 内，插件包名与来源不再能逃出归档目录或被视为 pnpm 参数，纯点号版本号也不再能清空整个 archive。
- **dsh 版本目录 / home 未校验**：官方安装对话框接受任意版本目录，且未净化的名称会拼入路径，点号片段会让 pnpm 操作、甚至在失败时删除父目录。现在版本目录与 home 会 resolve、类型检查，并在缺失时创建；安装名不会解析为点路径；空的 dshVersionDir 会像 pluginDir 一样回退默认值。
- **DSH 数据导入可被强制指向任意包**：data:import 此前信任渲染进程传入的任意文件路径。主进程现在记录原生对话框实际返回的归档，仅接受该路径且一次性使用。

#### 🏗️ 工程
- 抽出共享的路径 / 版本校验（core/name-guard.ts），IPC 与 core 复用同一套规则，避免重复实现。
- 测试范围纳入 src/main/ipc，新增名称、版本与路径越界的单元测试。

### English

#### 🐛 Fixes
- **The plugin library's pnpm store could land at a drive root**: with no store dir passed, pnpm computes its own from the user's home and, when the project sits on another volume, drops an unmanaged `.pnpm-store` at that drive's root. runPnpm now always injects the configured library store (wired once at startup), profile and dsh installs share the single cache, and profile import/export read pluginDir through its accessor so the default location applies.
- **IPC arguments could escape their tree**: renderer-supplied profile names reached profileDir unguarded, so a crafted value could read, overwrite, rename or delete outside the profiles tree, and profile import removed an arbitrary localSource path recursively. A shared name guard now backs both the ipc layer and the core store builders: every profile handler validates its name, import temp cleanup is confined to import-tmp, plugin names and sources cannot escape the archive or be parsed as pnpm flags, and dot-only versions can no longer wipe the whole archive.
- **dsh version dirs and homes were unvalidated**: the official-install dialog accepted any version dir and joined an unsanitized name onto it, so dot segments could make pnpm operate on, and on failure delete, the parent directory. Version dirs and homes are now resolved, type-checked and created when absent, install names cannot resolve to dot paths, and an empty dshVersionDir falls back to the default like pluginDir.
- **DSH data import could be forced to any archive**: data:import trusted any file path from the renderer; the main process now records the archive the native dialog returned and accepts only that path, once.

#### 🏗️ Engineering
- Extracted the shared path/version guards into core/name-guard.ts so the IPC and core layers reuse one implementation.
- Test scope now includes src/main/ipc with unit tests for the name, version and path-escape checks.
