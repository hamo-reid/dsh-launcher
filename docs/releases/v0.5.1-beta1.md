# DSH Launcher v0.5.1-beta1

> 本版主线是**装得上、看得出**：插件来源从「只认 GitHub 和 npm」扩展到 GitLab / Gitea / Gitee，下载失败不再是「失败」两个字而是一句原因加完整日志，插件总览能逐版本看磁盘占用；Profile 侧把「组合与诊断」做成唯一说「能不能启动」的地方，并修掉一个会给假保证的校验；预设页、运行页、bundle 层对话框重做。另有几处**看得见的**兼容性变化：启动横幅的框线字符此前在 Windows 终端里是乱码，现已修好。

### 中文版

#### ⚠️ 兼容性

- **设置 schema 不变**（仍为 v3），数据目录布局不变，升级与降级都不需要迁移步骤。
- 旧版本导出的 `settings.json` 可正常导入。
- **启动横幅与日志前缀的显示**：此前部分 Windows 终端会把横幅的 `█ ╔ ═ ╗` 显示成 `鈻堚枅`，紧随其后的日志行也会错位。原因是终端对「一次写入」整段只用一种代码页解码，而它会拒绝对一段较短的无色非 ASCII 文本做 UTF-8 判定；本项目从未指定控制台代码页。现在每行输出前都会带一个明确的 UTF-8 标记，且横幅自带换行、不再和下一条日志合并成一次写入。这是纯显示修复，`chcp` 之类的终端设置无需改动，也不受影响。
- **不再使用 antd 的 `List` 组件与 `Space direction` 属性**：它们在当前 antd 版本已弃用（控制台每次启动都在提示），`List` 还会在下一个大版本移除。改用等价的原生结构，界面与交互无变化。如果你在旧版上启动时会看到这两条弃用警告，本版起不再出现。

#### ✨ 新功能 · 插件来源

- **一次解析、多种源**：`github` / `gitlab` / `gitea` / `gitee` 走同一个纯函数解析器（`store/git-source.ts`），支持 `owner/repo`、各家的 URL 简写、`git+https://`、`git://`、`git@host:owner/repo.git`、带子组的 GitLab 路径，以及 `@scope/pkg@1.2.3` 形式的 npm 规格。全部离线判定，不触网。
- **认不出来的 git 主机仍按 git 源装**：认不出来的是「标签」，不是「可装性」—— pnpm 照单收下 URL，只是按既有的 git 归宿记账。
- **每家源各记各的出处**：安装后按实际主机记为 `github` / `gitlab` / `gitea` / `gitee`，插件详情里的来源标签不会再张冠李戴。
- **推出来的包名只是假设**：安装时用 `node_modules` 的实际结果反证；对不上时报错会**点出真实包名**，因为用户从头到尾没有输入过包名，只说「包名不匹配」等于把猜测的责任丢回给他。
- **更新检查的口径**：只有 GitHub 源能查标签（走 tags API）；其余宿主标为「手动」，而不是编一个检查结果。

#### ✨ 新功能 · 下载失败要说清楚

- **失败在失败点分类**：`not-found` / `auth` / `network` / `not-a-package` / `name-mismatch` / `version` / `peer` / `disk` / `script` / `aborted` / `unknown` 十一种，规则**按特征性从最具体到最宽泛**排序（同一段日志常常同时命中多个规则，比如 git 认证失败同时也是网络错误）。每条结论配一句可执行的下一步。
- **「详情」里是真详情**：分类结论、判定依据（原始报错行，逐字保留、可复制）、实际执行的命令、以及**未经截断的完整日志**。原因常常在日志开头（解析到哪一步失败），只留最后几行等于没有。
- **能说「不知道」**：`unknown` 保留日志尾部作为证据，而不是硬套一个像真相的猜测。
- **列表和提示条只给一句话**：一行放不下 pnpm 的输出，所以失败行与 toast 只显示原因，全量留给详情。
- **取消的会话保留已产生的日志**：中断不等于没有证据。
- **「本次下载」就地可见**：发起下载的页面就地显示这条会话的状态、原因与取消入口，输入框在提交后清空；并行下载照常，只拒绝「同一来源重复提交」。
- 时长（`850 ms` / `3.2 s` / `1 分 05 秒`）一并显示。

#### ✨ 新功能 · 插件总览的磁盘占用

- **逐版本显示大小**：插件详情里的「版本」列表，每行带该版本自己的磁盘占用。
- **两个数字互不换算**：插件总量是**去重后**的（所有归档版本共用一张 inode 表），单版本大小是**单独测量**的 —— 版本之间通过 pnpm store 的硬链接共享文件，所以各版本之和**可能大于**总量。因此不做「总量 ÷ 版本数」，也不拿版本之和冒充总量；差值只能解释为「共享字节」，界面上就写成「删掉它大致能腾出多少」。真无从判断时（没算总量、某版本未测到）不显示派生数字，某版本没测到时省略该键而不是记 0 —— 「不知道」和「空」必须能分开。

#### ✨ 新功能 · Profile

- **运行页改成卡片式选 dsh**：左侧不再是下拉框而是卡片列表，选中决定右侧内容；点卡片即按已保存的参数启动并直接跳到进程管理。
- **bundle 层对话框重做成左右分栏**：左侧是行卡片（标签标明是否禁用、是否被覆盖），点进右侧详情；覆盖 / 插入 / 删除等操作在右侧顶部。之前那个「改配置」的二级弹窗去掉，改为可返回的渐进式详情。
- **组合与诊断成为唯一说「能不能启动」的地方**：原先右侧还有一个「检查器」面板，它和诊断页都在说「问题」二字 —— 两个面板说同一件事就是一个多余。检查器的计数、判定与跳转并入诊断页，并且**每条发现都能点到能修它的地方**（patch 文件 / package.json / bundle 层）。
- **校验启动的判定改成按启动真正会读的东西**：它此前只解析 profile 自己的 patch，于是**bundle 的 `cordis.patch.yml` 根本不是 YAML 时它照样说「可以启动」**，用户点了启动才失败 —— 这比不检查更糟。现在它解析 profile patch 加上每个 bundle 的每个 patch 文件，**每个坏文件都报一次并带上它来自哪个 bundle**；profile 根本不存在时报的是 manifest 错误，而不是一份「空组合」的通过结论。
- 文案改成结论口气：「可以启动」/「现在启动会失败」，而不是过程口气的「组合检查通过」。

#### ✨ 新功能 · 预设页

- **一级「预设」标签页**已在上版落地，本版继续打磨页面头部：标题只报数据（一个标题 + 一行名册摘要 + 控件），「评级是什么意思」「名册由哪套模型决定」这类参考材料收进「说明」。
- 每一行只在**行本身**可点击并打开内容，右侧控件是它的**兄弟节点**，点控件不会顺带打开弹窗。
- 每行两个控件：「打开」下拉（在文件管理器里显示 / 用 VS Code 打开）和一个「…」菜单（编辑描述 / 复制 / 删除）。

#### 🐛 Bug 修复

- **启动横幅乱码**（见上「兼容性」第一条）。
- **校验启动给假保证**（见上「Profile」第三条）。
- **bundle 的多文件 patch 此前只被读成第一个文件**，一个健康的 profile 会因此被报出幽灵冲突。
- **清单 / patch 解析错误只有一个字段**：现在多文件会逐条报，且 `patchError` 仍取第一条以便只显示一行的地方也说的是真话。
- **失败的下载会话被静默丢弃**：现在以失败态留在列表里，可点开看原因与日志。

#### ⚡️ 优化

- 插件安装失败不再只有退出码，而是分类结论 + 完整输出。
- 预检失败在**启动 pnpm 之前**就给出拒绝（例如来源为空、路径非法），不再花一次网络往返去换一个必然失败。
- 组合检查在多 bundle 的情况下只构建一次搜索根，不再每个 bundle 重走一遍安装锚点。

#### 🔧 工程 / 架构

- **控制台输出统一走 `core/shared/console.ts`**：UTF-8 标记与原始字节写出集中在一处，横幅图案与布局断言也在同一模块，避免「别处再写一份」。
- **校验的判据落进 `docs/specs/profile.md` P15**：能不能启动必须按启动真正会读的东西判；独立检查器面板与诊断页不得都声称自己说的是全部问题。
- **来源解析落进 `docs/specs/profile.md` P13**：从外部字符串推出来的包名只是假设，必须由安装结果反证；源的类型识别只有一个实现。
- **两个大小数字落进 `docs/specs/profile.md` P14**：互不可换算，不得互相冒充。
- 新增用例：来源解析 25 条、失败分类 27 条、逐版本大小 4 条、渲染侧换算 12 条、控制台编码 11 条、组合校验 4 条，以及 bundle 层对话框、预设详情、运行页卡片、编辑器对话框的渲染用例。
- 去掉了 antd 已弃用的 `List` 与 `Space direction`，控制台不再在每次启动时打印这两条警告。

### English

#### ⚠️ Compatibility

- **Settings schema is unchanged** (still v3); data-directory layout is unchanged, so upgrading and downgrading need no migration step. A `settings.json` exported by an older build imports normally.
- **Launch banner and log prefixes**: some Windows terminals used to render the banner's `█ ╔ ═ ╗` as `鈻堚枅`, and the log lines right after it lost their alignment. A terminal decodes one console write as a whole with a single code page, and it refuses the UTF-8 guess for a short, colourless run of non-ASCII text — the app never chose a code page. Every line is now emitted with an explicit UTF-8 marker, and the banner carries its own newline instead of being glued to the next log line in one write. Display-only fix; terminal settings such as `chcp` need no change and are not affected.
- **antd's `List` and `Space direction` are gone**: both are deprecated in the installed antd (they printed a warning on every start) and `List` is removed in the next major. They are replaced with equivalent plain markup; no visual or behavioural change. Those two warnings no longer appear.

#### ✨ New · Plugin sources

- **One parser, several forges**: `github` / `gitlab` / `gitea` / `gitee` share a single pure parser (`store/git-source.ts`) handling `owner/repo`, each forge's shorthand URL, `git+https://`, `git://`, `git@host:owner/repo.git`, GitLab subgroups, and npm specs such as `@scope/pkg@1.2.3`. All offline.
- **An unrecognised git host still installs as a git source**: what the parser fails to recognise is the label, not the installability — pnpm takes the URL, and the plugin is recorded under the existing git origin.
- **Each forge keeps its own recorded origin**, so the source tag on a plugin's detail no longer mislabels where it came from.
- **A derived package name is only a hypothesis**: it is re-verified against `node_modules`, and a mismatch names the real package, because the user never typed a package name and "name mismatch" alone would hand the failure back to them.
- **Update checks stay honest**: only GitHub origins consult the tags API; other hosts are reported as manual rather than given an invented verdict.

#### ✨ New · Download failures that explain themselves

- **Classified where they happen**: eleven kinds (not found, auth, network, not-a-package, name mismatch, version, peer, disk, script, abort, unknown), with rules ordered most-specific first — one log usually matches several (a git auth failure is also a network error) — and one executable next step per verdict.
- **"Details" means real details**: the verdict, the verbatim evidence lines, the command that ran, and the **full, untruncated log**. The reason is often at the top of the log (where resolution failed), so keeping only the tail is keeping nothing.
- **It can say "unknown"**: that kind keeps the tail as evidence instead of forcing a plausible-sounding guess.
- **Rows and toasts carry one sentence**; the rest lives behind Details.
- **A cancelled session keeps the log it already produced** — an interruption is not the absence of evidence.
- **"This download" is visible where it started**: the launching page shows that session's state, cause and cancel entry inline, and clears the input after submitting. Parallel downloads are unaffected; only a duplicate submission of the same source is refused.
- Durations are shown as `850 ms` / `3.2 s` / `1 min 05 s`.

#### ✨ New · On-disk size in the plugin overview

- **Per-version sizes**: each archived version's row in the plugin detail shows that version's own footprint.
- **Two numbers that never convert into each other**: the plugin total is **deduplicated** (one inode table for all archived versions); a per-version size is **measured alone**, and because pnpm's store hard-links shared files, the per-version sizes can add up to **more** than the total. So the total is never divided by the version count and the sum is never presented as the total; the difference is only explainable as shared bytes, and the UI phrases a per-version number as "roughly how much deleting it frees". When a derived number cannot be known (no total yet, or that version unmeasured) nothing is shown, and an unmeasured version is omitted rather than recorded as 0 — "unknown" and "empty" must stay distinguishable.

#### ✨ New · Profiles

- **The run page picks a dsh from cards**, not a dropdown; the selection drives the right-hand side, and clicking a card launches with its saved options and jumps straight to the process console.
- **The bundle layer dialog is a two-pane row detail**: cards on the left (tagged disabled / overridden), the selected row's detail on the right, with cover / insert / delete at the top of the detail. The extra "edit config" modal is gone, replaced by a progressive detail with a back button.
- **Composition & diagnostics is now the only place that answers "will this boot"**: the old inspector rail and the diagnostics tab both claimed to list "the problems", which is one panel too many. The inspector's counts, verdict and jumps moved into the report, and every finding now links to the section that can fix it (patch file / package.json / bundles).
- **The launch check judges what a boot actually reads**: it used to parse the profile's own patch only, so **a bundle whose `cordis.patch.yml` was not even YAML still came back "can start"** and the user found out by launching — worse than not checking. It now parses the profile patch plus every patch file of every bundle, reports **each** broken file with the bundle it comes from, and treats a missing profile as a manifest error rather than an empty composition that passes.
- The wording states the verdict — "can start" / "starting this profile would fail" — instead of describing the check.

#### ✨ New · Presets

- The first-class **Presets** tab landed in the previous beta; this one finishes the header: a title, one line summarising the roster and the controls. What a grade means and which model decides the roster are reference material and live behind the header's own help.
- Only the **row itself** opens the contents; its controls are siblings, so clicking one never also opens the dialog.
- **Open** dropdown (reveal in the file manager / open in VS Code) plus a "…" menu (edit description / copy / delete).

#### 🐛 Fixes

- **The launch banner mojibake** (see the first compatibility note).
- **The launch check giving a false all-clear** (see the third Profile note).
- **A bundle's multi-file patch used to be read as its first file only**, which reported a phantom conflict on a healthy profile.
- **One field for manifest / patch parse errors**: several broken files are now reported one per line, while `patchError` keeps the first for the places that show a single line.
- **A failed download was dropped silently**; it now stays in the list as a failure that can be opened for its cause and log.

#### ⚡️ Improvements

- A failed install reports a classified verdict plus the full output instead of one exit code.
- Pre-flight refusals (empty source, traversal in a path) happen **before** pnpm is started, instead of spending a round trip on a guaranteed failure.
- The composition check builds its search roots once for many bundles instead of re-walking the install anchor per bundle.

#### 🔧 Engineering

- **Console output goes through `core/shared/console.ts`**: the UTF-8 marker and raw-byte writes live in one place, next to the banner art and its layout assertions, so no second copy appears elsewhere.
- **The launch-check rule is written down as `docs/specs/profile.md` P15**: judge bootability by what a boot reads, and never have two panels both claim to list all problems.
- **The source rule is P13**: a name derived from an external string is a hypothesis to be re-verified, and source classification has a single implementation.
- **The two size numbers are P14**: they are not interchangeable, and neither may stand in for the other.
- New tests: 25 for source parsing, 27 for failure classification, 4 for per-version sizes, 12 for the renderer-side conversion, 11 for console encoding, 4 for the composition check, plus render tests for the bundle layer dialog, preset detail, run-page card and editor dialogs.
- antd's deprecated `List` and `Space direction` are gone, so those two warnings no longer print on every start.
