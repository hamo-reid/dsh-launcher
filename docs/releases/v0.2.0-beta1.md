# DSH Launcher v0.2.0-beta1

### 中文版

#### ⚠️ 破坏性更新（插件库管理）
- **商店布局不兼容**：插件存储从 v0.1.4 及更早的扁平布局（`<store>/node_modules/<name>`，每插件仅一版）迁移为**多版本归档**（`<store>/archive/<name>/<version>/`，每版本自包含、同名插件可共存多版并独立管理）。
- **升级后自动一次性迁移**：首次触发商店写操作时，旧扁平插件被自动搬运并重建到归档布局，随后旧扁平包及其 manifest 依赖会被移除；已引用旧 store 包路径的 profile 会被自动改写为指向新版本目录。
- **迁移有网络兜底**：优先从本地缓存离线复装；缓存缺失时需联网重试，个别无法迁移的包会被跳过并在日志告警。
- **不可回退**：布局变更后，旧版（v0.1.4 及更早）无法直接读写同一插件存储；如需回退请先备份插件目录。

#### ✨ 功能
- **社区市场**：浏览并安装策划好的 dsh 插件；列表分页 + 本地切片，GitHub 来源条目与插件商店对齐。
- **多版本插件商店**：`archive/<name>/<version>/` 版本化归档，同名插件可共存多版本；提供一次性旧版（v0.1.4 flat）商店迁移。
- **版本级插件管理**：按版本安装来源标记（GitHub / npm / 本地文件），支持级联卸载与来源标签展示。
- **插件总览增强**：总览列出各来源标签，并展示按 inode 去重后的真实磁盘占用；从市场/下载返回时自动刷新，已下载插件即时上架。
- **统一下载中心**：DSH 安装/更新与插件安装共用同一下载中心，实时进度与可取消的插件下载。
- **聚合插件包（bundle）**：可靠加载聚合 bundle、去重归档层依赖、按语义化版本（semver）而非字典序排序归档版本。
- **启动轻量化**：Portable / 冷启动时展示轻量 splash，避免启动空白。
- **启动器自更新检测**：关于页检查 GitHub Releases 是否有更新版本（含 beta 预发布）。

#### 🐛 修复
- 从 app.asar.unpacked 正确解析内置 pnpm，修复 Portable / 打包后打包失败。
- 插件总览缺失来源/排序问题：按 semver 排序归档版本、来源标签跟踪不随 pnpm manifest 重写丢失。
- 顶置品牌行不再被 Modal / Drawer 遮罩层遮挡；下载中心仅在打开对应视图时才查询。

#### 🏗️ 工程 / 安全
- 渲染层代码分割（vendor chunks）+ 视图懒加载，启动体积与首屏更轻。
- 完成 CSP；修正两处 preload contract 漂移。
- 移除 `profile:launch` shell 注入面、收紧 webContents 导航（默认拒绝非 app 自有 URL）。
- 收敛 contract 类型、清理死代码与遗留 shim；统一 `majorOf` 解析。
- 拆分存储模块并提升关键失败分支的测试覆盖率；对齐 RELEASE.md 与 BRANCHING.md。

### English

#### ⚠️ Breaking change（plugin store management）
- **Incompatible store layout**: the plugin store moves from the v0.1.4-and-earlier flat layout (`<store>/node_modules/<name>`, one version per plugin) to a **multi-version archive** (`<store>/archive/<name>/<version>/`, each version self-contained, several versions of the same plugin can coexist and be managed independently).
- **One-time automatic migration on upgrade**: the first store write after upgrading rebuilds legacy flat plugins into the archive layout, then removes the old flat packages and their manifest dependencies; profiles already referencing a legacy store path are retargeted to the new version directory.
- **Network-backed migration**: prefers an offline reinstall from the local cache; falls back to the network when the cache misses. Packages that cannot be migrated are skipped and warned in the logs.
- **Not reversible**: after this layout change, older builds (v0.1.4 and earlier) can no longer read/write the same plugin store. Back up your plugin directory before downgrading.

#### ✨ Features
- **Community market**: browse and install curated dsh plugins; paginated + locally sliced list, GitHub-sourced entries aligned with the plugin store.
- **Multi-version plugin store**: versioned `archive/<name>/<version>/` layout, so several versions of a plugin can coexist; one-time migration from the legacy (v0.1.4 flat) store.
- **Per-version plugin management**: install source tagging (GitHub / npm / local folder), cascading uninstall, and source labels.
- **Richer plugin overview**: source tags and inode-deduped on-disk sizes; refreshes on returning from market/download, downloaded plugins show up immediately.
- **Unified download center**: DSH installs/updates and plugin installs share one center with live progress and cancellable plugin downloads.
- **Aggregate bundles**: reliable aggregate-bundle loading, deduped archive dependencies, semver-ordered (not dictionary) archived versions.
- **Lightweight cold startup**: a slim splash during Portable / cold start, no startup blank.
- **Launcher self-update check**: the About page checks GitHub Releases for a newer build (beta prereleases included).

#### 🐛 Fixes
- Resolve the bundled pnpm from `app.asar.unpacked`, fixing packing after a Portable / packaged build.
- Overview source/sorting issues: archive versions order by semver; source tags survive pnpm manifest rewrites.
- The on-top brand row is no longer masked by Modal/Drawer overlays; the download center only queries after that view is opened.

#### 🏗️ Engineering / Security
- Renderer code-splitting (vendor chunks) + lazy-loaded views for a lighter startup and bundle.
- Completed CSP; aligned two preload contract drifts.
- Removed the `profile:launch` shell-injection surface and tightened webContents navigation (default-deny for anything but the app's own URL).
- Collapsed duplicated contract types, dead code and stale shims; unified `majorOf` parsing.
- Split the store modules and raised failure-branch test coverage; aligned RELEASE.md with BRANCHING.md.
