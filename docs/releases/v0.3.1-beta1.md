# DSH Launcher v0.3.1-beta1

> 本版主线是**插件开发体验**：本地文件夹可作为「开发插件」以链接方式接入 profile，改代码即由 dsh 的 HMR 热重载；同时补齐插件总览的版本管理闭环与筛选排除。建议升级前备份 `~/dsh-launcher`。

### 中文版

#### ✨ 新功能 · 开发插件（Dev plugins）

- **本地文件夹直接接入**：新增「开发插件」分区，选一个包目录即可注册；profile 以 `link:<源码目录>` 解析你的包（**不拷贝**），改代码保存即由 dsh 的 HMR 热重载（启动参数已常开 `--expose-internals`）。
- **与插件库独立管理**：开发插件有自己的注册表（存在 launcher 设置里），**不参与**更新检查、版本管理与库清理；移除注册**不会**删除你的源码。
- **按实际 patch 解析**：开发 bundle 的 `dsh.bundle.patch` 每一行 `name:` 才是 dsh 真正加载的模块；逐行解析并报告，**不扫描整个 workspace**。
- **解析诊断 + 一键修复**：入口（构建产物）是否缺失、patch 行与宿主 peer（`@deepseek-ai/*`）是否可解析，都逐条列出并标注**命中来源**（monorepo / 宿主 / 宿主·兜底 / home）。`link:` 的 peer 从开发包解析而非 profile，所以提供「在仓库安装」（推荐）与「补 peer（shim）」（可撤销兜底）两种修复。
- **构建**：可选的构建动作，**脚本名与执行位置可选**（本包 / 工作区根，适配 monorepo 把聚合 `build` 放在根上的情况）并**记住选择**；结果弹窗显示**工作目录 + 可复制的完整命令**与 pnpm 输出。
- **毕业路径**：`快照到库` 把当前源码状态归档为版本，之后即可用普通插件的方式固定/切换版本。

#### ✨ 新功能 · 插件总览

- **版本下载与更新**：总览卡片可直接「下载版本…」（列出全部 npm 版本与 dist-tags）；有更新时出现「更新」按钮，打开弹窗可选**任意版本（含更旧）**。
- **更新是逐 profile 可选的**：默认**只归档版本到插件库**；勾选「应用至已安装的 profile」后展开**只含已安装该插件的 profile** 的多选列表（显示各自解析到的版本），默认一个都不选。另有「保留旧版本」开关（默认保留；取消则应用后清理不再使用的旧版本）。
- **替换 profile 的 bundle 版本**：Profile → Bundle 层每行显示 `@版本` + 来源标签（内置 / 库 / npm / 本地），可**替换版本**（库内或 npm 版本）；内置与本地路径来源只读。本地来源另有「重新链接」修复。

#### ✨ 新功能 · 筛选

- **按条件排除**：总览的每个维度（归档来源 / 类型 / 管理来源）都有 `包含 / 排除` 开关；同维度内多选仍 OR，跨维度仍 AND。chips 以 `类型 ≠ 内置` 显示排除项，筛选条件本地记忆（旧格式自动迁移，不丢已有筛选）。

#### ✨ 新功能 · GitHub 认证

- **更新检查可带令牌**：`safeStorage` 加密保存的 GitHub Token（也可用 `GH_TOKEN` / `GITHUB_TOKEN` 环境变量），把 API 上限从 60 次/小时提升到 5000；设置页可保存 / 测试 / 清除，并显示令牌来源与是否加密。令牌**不写日志、不进设置导出**。

#### 🐛 修复

- **下载失败不再静默**：会话进入终态即被移出活动列表，此前失败会**连行一起消失**。现在终态会一次性推送：失败时弹错误提示，并在下载中心保留该行（含具体报错）直到手动忽略。
- **DSH 安装/更新后侧边栏不刷新**：此前监听的是永远不会下发的 `done` 快照；改为在会话结束时刷新列表，安装完成即时可见。
- **开发插件构建必然失败**：`runPnpm` 默认注入的 `--store-dir` 被 pnpm 10 视为 `run` 的未知选项；脚本调用现在不再注入（用户自己的仓库用自己的 store）。

#### 🎨 体验 / 界面

- 总览默认**隐藏开发插件**（避免与正式插件混在一起），工具栏可勾选「显示开发插件」。
- 构建/安装结果弹窗显示**工作目录**与**可复制命令**，便于在终端复现。
- 开发插件的解析诊断用**来源标签**区分 monorepo 与宿主提供，避免把宿主包误报为缺失。

#### 🏗️ 工程 / 文档

- **破坏性操作护栏**：新增 `AGENTS.md` 硬性规则与 `scripts/safe-remove.ps1`（越界即拒绝、支持 `-WhatIf`）；`TROUBLESHOOTING §7` 记录误删事故复盘与**实测**有效的防护。
- `TROUBLESHOOTING §10`：本地 / monorepo 插件开发（dev link · patch 解析 · peer 解析 · HMR · 缺失链接修复）。
- 测试：新增开发插件（注册/诊断/peer shim/构建目标）、总览筛选（含排除与旧格式迁移）、下载会话终态、命令回显等用例。
- 无新增运行时依赖。

### English

> This release is about the **plugin development experience**: a local folder can be attached as a "dev plugin" and linked into a profile, so edits hot-reload through dsh's HMR. It also completes the overview's version-management loop and adds filter exclusions. Back up `~/dsh-launcher` before upgrading.

#### ✨ Features · Dev plugins

- **Attach a local folder**: a new "Dev plugins" section registers a package dir; a profile then resolves it via `link:<source dir>` (**no copy**), so saving a file hot-reloads through dsh's HMR (`--expose-internals` is always passed).
- **Managed separately from the store**: dev plugins have their own registry (in launcher settings) and are **never** update-checked, version-managed or garbage-collected; unregistering **never** deletes your source.
- **Patch-driven resolution**: a dev bundle's `dsh.bundle.patch` rows are the modules dsh actually loads; each is resolved and reported — **no whole-workspace scan**.
- **Diagnosis + one-click fixes**: the entry build output, the patch rows and the host peers (`@deepseek-ai/*`) are listed with the **root that satisfied them** (monorepo / host / host fallback / home). A `link:`'s peers resolve from the dev package, not the profile, so both "install in workspace" (preferred) and "shim peers" (reversible fallback) are offered.
- **Build**: an optional build action whose **script and scope are selectable** (package / workspace root, for monorepos that keep the aggregate `build` at the root) and **remembered**; the result modal shows the working directory plus a **copyable command** and pnpm's output.
- **Graduation**: "Snapshot to store" archives the current source as a version, after which it can be pinned/version-managed like any plugin.

#### ✨ Features · Plugins overview

- **Download and update versions**: a card can "Download version..." (all npm versions + dist-tags); when an update exists an "Update" button opens a dialog to pick **any version (including older ones)**.
- **Updates are opt-in per profile**: by default the version is **only archived into the store**; ticking "Apply to installed profiles" reveals a multi-select of **only the profiles where it is already installed** (each showing its resolved version), starting with nothing ticked. A "Keep the old version(s)" switch (on by default; off cleans up unused older versions after applying).
- **Replace a profile bundle's version**: each Bundle-layer row shows `@version` plus source tags (in-box / store / npm / local) and can **replace its version** (store or npm); in-box and local-path sources stay read-only, with a "relink" repair for local ones.

#### ✨ Features · Filters

- **Exclude by condition**: every overview dimension (origin / kind / provenance) has an `Include / Exclude` switch; values still OR within a dimension and AND across. Chips render `kind != template` for excluded values, and the config is remembered locally (the old shape is migrated, so an existing filter is never lost).

#### ✨ Features · GitHub auth

- **Authenticated update checks**: a GitHub token stored encrypted via `safeStorage` (or `GH_TOKEN` / `GITHUB_TOKEN`) raises the API limit from 60/h to 5000/h; the Settings page can save / test / clear it and shows its source and whether it is encrypted. The token is never logged and never exported.

#### 🐛 Fixes

- **Failed downloads are no longer silent**: a settled session leaves the live list, so a failure used to vanish with its row. The terminal state is now pushed once: a failure raises an error toast and the row is kept in the download centre (with its message) until dismissed.
- **The DSH list did not refresh after an install/update**: it listened for a `done` snapshot that was never emitted; it now refreshes when a session settles, so a finished install appears immediately.
- **The dev-plugin build always failed**: `runPnpm` injected `--store-dir` by default, which pnpm 10 rejects for `run`; script invocations no longer inject it (the user's own repo uses its own store).

#### 🎨 UX / UI

- The overview **hides dev plugins** by default (they no longer mix with regular plugins); a toolbar checkbox shows them.
- Build/install result modals show the **working directory** and a **copyable command**, so it can be reproduced in a terminal.
- Dev-plugin diagnosis labels the **source root**, so host-provided packages are no longer misreported as missing.

#### 🏗️ Engineering / docs

- **Destructive-command guardrails**: `AGENTS.md` hard rules plus `scripts/safe-remove.ps1` (refuses any target outside an allowed root, supports `-WhatIf`); `TROUBLESHOOTING section 7` records the data-loss post-mortem and which mitigations actually work.
- `TROUBLESHOOTING section 10`: local / monorepo plugin development (dev link, patch resolution, peer resolution, HMR, missing-link repair).
- Tests: added coverage for dev plugins (registry / diagnosis / peer shim / build target), overview filters (including exclusions and legacy migration), download terminal states and command echo.
- No new runtime dependencies.
