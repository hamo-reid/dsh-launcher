# DSH Launcher v0.6.0-beta1

> 本版主线是**把「从哪装」变成一个显式、可验证的选择**：npm 私有源从一个地址扩成一张源表（每条源认领若干作用域，另有显式的镜像模式），社区市场从一个写死的地址变成一个命名目录列表，配置项从市场页搬进设置。第二条主线是**同一个包可以同时有两种身份**——本地开发中的目录与库里已发布的版本——本版让它们共存而不再互相顶替，并且谁在生效一眼可见。

### 中文版

#### ⚠️ 兼容性

- **设置 schema 从 v3 升到 v6**，三次迁移在打开数据库时自动完成，无需手动步骤：
  - v3 → v4：单条私有源的「地址 + 作用域 + 令牌」变成一个源表条目；
  - v4 → v5：每条源的单作用域变成多作用域；
  - v5 → v6：单一的市场地址变成一个命名目录列表，旧的地址被包成第一条目录（名称取主机名），令牌一并搬迁。
- **旧版打开新版数据不会损坏**：设置版本只升不降，旧版不会把自己的版本号盖回去。但 v6 引入的市场目录列表在旧版里不可见——旧版仍按它认识的单地址字段工作。
- **导入导出**：旧版导出的 `settings.json` 仍可正常导入；新版导出的文件被旧版导入时会**明确报错**（`settings export is newer`），而不是静默丢掉不认识的字段。
- **生成的 `.npmrc` 只在配置了源时才写**；没有配置任何源时，安装流程与之前完全一致。
- **镜像源是显式开关**：打开时明确写着「所有包都从这里取，包括公共包」，默认关闭。

#### ✨ 新功能 · npm 私有源

- **源表取代单一地址**：任意数量的源，每条有名称、地址、一个或多个作用域，可单独保存令牌（加密存放）。
- **作用域决定路由**：`@scope` 的包走认领它的那条源，其余一律走公共 npm。每条源**必须**至少填一个作用域——没有「兜底源」这种含糊的中间态，找不到归属的包直接走官方源，没有歧义。
- **镜像源**：一次打开就代理所有包下载，界面上带硬提示；它和按作用域的源**可以并存**，作用域优先。
- **记录「谁回答的」**：安装时把回答的源 id 写进 `.pm-sources.json`，插件总览里显示该源的名称，不再只有「npm」一个笼统标签。
- **下载页可以选来源**：公共源或任意一条配置好的源，选定后版本列表来自该源；包名落在所选源的作用域之外时会明确提示。
- **测试连接会说人话**：公共源与私有源分开探测，镜像模式额外报告代理是否可达。

#### ✨ 新功能 · 社区市场目录

- **目录变成命名列表**（schema v6）：公共目录内置、不可改名不可删除、永远排第一；私有目录数量不限、可命名、可改可删。
- **新建目录用弹窗，令牌在同一次保存里写入**——不再有「先存目录、再补令牌」的两步窗口，弹窗关掉时目录已经能用了。
- **保存时校验地址**：真的去取一次，返回的不是插件列表就拒绝保存。网页链接（`/-/blob/…`）和原始文件在输入框里长得一模一样，而 CNB 对网页回 400、对原始文件回 200——这个错误必须在保存时报出来，而不是等到第一次刷新。
- **失败原因分开说**：地址不是 http(s)、名称为空、名称重复、取不到（附 HTTP 状态）各有各的句子，不再把三条规则揉成一句让人猜。
- **401 与 400 区分**：前者是令牌不被接受，后者常常是主机不接受令牌（例如把网页域当成 API 域）。
- **市场页只负责选**：下拉切换当前目录，切换是浏览行为，立刻重新拉取；配置本身在设置里。

#### ✨ 新功能 · 开发插件与库中版本共存

- **同一个包名的两种身份可以同时存在**：本地开发目录（`link:`）与库里归档的版本（`file:`）。一个 profile 只能绑其中一个——Node 按包名解析到唯一目录——但另一个**不会被删除**，随时可切回。
- **绑定是推导出来的**，不是另存一份记录：从 profile 的依赖 spec 判定，避免记录与实际不一致。
- **替换本地链接前先问**：装库中版本时若该 profile 正绑着 dev 链接，弹出确认并说明「开发插件本身不会被删除」。
- **快照不得顶替发布件**：归档里已存在同一版本、且它来自 registry 时，本地快照默认被拒绝（可显式强制）。否则「我装的是 1.0.0」从此说不清是哪个 1.0.0。
- **绑 dev 的包不参与更新检查**：没有已发布对应物可比，去问 registry 等于回答一个「这台机器没在跑的构建」。
- **总览上的身份徽标**：`本地链接` / `混合绑定`（不同 profile 绑了不同身份）/ `外部链接`；普通的库中版本不加标签——每行都加等于什么都没说。
- **开发插件列表重读版本**：版本标签此前只在登记那一刻写一次，之后改了 `package.json` 仍显示旧号；现在列出来之前会重新读一次。

#### 🐛 Bug 修复

- **市场目录列表刷新后消失**：面板只在增删改的返回值里赋值，挂载时从未加载——数据一直在磁盘上，只是没人去读。
- **保存按钮没有在途状态**：失败时弹窗不关、按钮不禁用，连点几次就叠加几条一模一样的报错。
- **目录卡片标题重复 owner**：scoped 包名被渲染成 `scope/@scope/pkg`，因为 owner 已经在名字里。
- **私有目录永远存不进去**：保存前的探测取不到尚未写入的令牌，私有目录必然被判失败（本版修复：令牌随保存请求一起传）。
- **继承的 `npm_config_*` 覆盖生成的 registry**：`pnpm run` 会把这些环境变量带进启动器进程，而环境变量优先级高于任何 npmrc（本版修复：启动 pnpm 前清掉它们）。
- **`ERR_PNPM_NO_MATCHING_VERSION` 报错了包名**：pnpm 在缺失版本属于依赖时会追加 `while fetching it from …`，锚定行尾的匹配因此归咎于错误的包（本版修复）。
- **同一版本被重发布后安装失败**：pnpm 的元数据缓存与 profile lock 里留着旧的 `dist.integrity`，重装要么重放旧字节、要么报 `ERR_PNPM_TARBALL_INTEGRITY`（本版修复：下载与安装前刷新元数据）。

#### ⚡️ 优化

- **不再冒充 GitHub**：市场条目的详情按钮只有在地址确实是 GitHub 时才显示 GitHub 图标，其余显示「打开来源」。
- **文案去掉本机痕迹**：占位符此前写的是某台机器上的具体名称与作用域，全部换成中性表述（`名称`、`@myorg`）。
- **页头不再替某个目录做宣传**，也不再承诺私有目录没有的字段（星星、下载量）。

#### 🔧 工程 / 架构

- **新增 `store/binding.ts`**：绑定推导与聚合是纯函数，不碰文件系统，9 条用例覆盖「大小写/尾斜杠不同仍是同一目录」「非登记目录的链接是 external 而不是 dev」「多 profile 不一致时是 mixed」。
- **`installSource` 记录归档来源**：`.pm-sources.json` 每条多一个 `snapshot` 标记，区分本地快照与 registry 下载——这是同一版本保护能成立的前提。
- **`syncDevVersions` 有独立用例**：改版本后写回、manifest 读不到时保留原值、未变化时对象完全相等。
- **两条判据落进 `docs/specs/profile.md`**：P16（一条源必须认领作用域，不存在「兜底源」）、P17（同一个版本号不能同时代表两种来源）。
- 测试规模：101 个测试文件，`pnpm typecheck` / `pnpm test` / `pnpm run build` 三道门禁全绿。

### English

#### ⚠️ Compatibility

- **Settings schema goes from v3 to v6**, with three migrations applied when the database opens; no manual step:
  - v3 → v4: one private source's address, scope and token become one entry in a source table;
  - v4 → v5: a source's single scope becomes several;
  - v5 → v6: the single market address becomes a named catalog list; the old address is wrapped as the first catalog (named after its host) and its token moves with it.
- **An older build opening newer data does not corrupt it**: the settings version only moves forward, and an older build never stamps its own number back over a newer one. The v6 catalog list is simply invisible to it — it keeps working with the single address field it knows.
- **Import / export**: a `settings.json` exported by an older build still imports normally; one exported by this build is **refused with a clear error** (`settings export is newer`) instead of silently dropping the fields it does not know.
- **The generated `.npmrc` is written only when a source is configured**; with none, installing behaves exactly as before.
- **Mirror mode is an explicit switch**: turning it on says plainly that every package — public ones included — comes from it, and it is off by default.

#### ✨ New · Private npm sources

- **A source table replaces the single address**: any number of sources, each with a name, an address, one or more scopes, and its own encrypted token.
- **Scopes decide routing**: a `@scope` package goes to the source that claimed it, everything else to public npm. Every source **must** claim at least one scope — there is no ambiguous fallback entry; an unclaimed package simply goes to the official registry.
- **Mirror mode** proxies every download with a hard warning on screen; it may coexist with scoped sources, where the scope wins.
- **The answering registry is recorded**: its id is written into `.pm-sources.json`, and the plugin overview shows that source's name instead of one blanket "npm".
- **The download page picks the source**: public or any configured one, with the version list coming from it, and a clear warning when the package name falls outside that source's scopes.
- **"Test connection" reports what it found**: public and private sources are probed separately, and mirror mode additionally reports whether the proxy is reachable.

#### ✨ New · Market catalogs

- **Catalogs are a named list** (schema v6): the public one is built in, cannot be renamed or removed, and is always first; private ones are unlimited, named, and editable.
- **Creating one is a modal, and the token is written in the same save** — there is no longer a window where a catalog exists but cannot authenticate.
- **The address is checked when saving**: it is actually fetched once, and anything that is not a plugin list is refused. A web page URL (`/-/blob/…`) and a raw file URL look identical in a text box while CNB answers 400 and 200 respectively — that mistake has to surface at save time, not at the first refresh.
- **Failures say which rule broke**: not http(s), empty name, duplicate name, or unreachable (with the HTTP status) each get their own sentence.
- **401 and 400 are told apart**: the first is a rejected token, the second is usually a host that refuses tokens at all (a web host used as an API host).
- **The market page only chooses**: a dropdown switches the active catalog — a browsing act that refetches immediately. Configuration lives in Settings.

#### ✨ New · A dev plugin and a published version can coexist

- **Two identities for one name**: a local source directory (`link:`) and an archived version in the store (`file:`). A profile binds exactly one — Node resolves a name to one directory — but the other is **never deleted** and can be switched back to.
- **The binding is derived**, not stored a second time: it is read from the profile's dependency spec, so a record cannot disagree with reality.
- **Replacing a dev link asks first**, and says that the dev registration survives.
- **A snapshot may not stand in for a published version**: when the archive already holds that version and it came from a registry, the local snapshot is refused by default (it can be forced). Otherwise "I have 1.0.0 installed" no longer says which 1.0.0.
- **A dev-bound package is not update-checked**: there is no published counterpart to compare against, and asking would answer about a build this machine is not running.
- **Identity badges in the overview**: `Dev link` / `Mixed` (profiles disagree) / `External link`. A plain store version carries no badge — a tag on every row says nothing.
- **The dev list re-reads the version**: the tag used to be written once at registration, so a bumped `package.json` kept showing the old number.

#### 🐛 Fixes

- **The catalog list vanished after a refresh**: the panel was only ever filled from a mutation's return value and never loaded on mount — the data was on disk all along.
- **The save button had no in-flight state**: a failed save left the dialog open with nothing changed, and every extra click stacked another identical error.
- **A scoped package rendered its owner twice** (`scope/@scope/pkg`), because the name already carries it.
- **A private catalog could never be saved**: the pre-save probe could not see a token that had not been stored yet (fixed in this release: the token travels with the save request).
- **Inherited `npm_config_*` overrode the generated registry**: `pnpm run` exports them into the launcher process, and an environment variable outranks every npmrc (fixed in this release: strip them before spawning pnpm).
- **`ERR_PNPM_NO_MATCHING_VERSION` named the wrong package**: pnpm appends `while fetching it from …` when the missing version is a dependency (fixed in this release).
- **Re-publishing the same version broke installs**: pnpm's metadata cache and the profile lock kept the old `dist.integrity`, so a reinstall replayed stale bytes or failed with `ERR_PNPM_TARBALL_INTEGRITY` (fixed in this release: refresh metadata before downloading and installing).

#### ⚡️ Improvements

- **No more pretending to be GitHub**: the market detail button shows the GitHub mark only when the address really is GitHub, and "open source" otherwise.
- **Copy without local fingerprints**: placeholders used to name one machine's own names and scopes; they are neutral now (`名称`, `@myorg`).
- **The page header no longer advertises one catalog**, and no longer promises fields a private catalog does not have (stars, download counts).

#### 🔧 Engineering

- **New `store/binding.ts`**: derivation and aggregation are pure functions with no filesystem access, covered by nine cases — including "the same directory in another case or with a trailing separator", "a link that is not a registered dev plugin is `external`, not `dev`", and "profiles that disagree aggregate to `mixed`".
- **`installSource` records where an archived version came from**: each `.pm-sources.json` entry carries a `snapshot` marker separating a local build from a registry download — the premise the same-version guard rests on.
- **`syncDevVersions` has its own cases**: a bumped version is written back, an unreadable manifest keeps the recorded value, and an unchanged plugin comes back equal.
- **Two rules are written down in `docs/specs/profile.md`**: P16 (a source must claim scopes; there is no fallback entry) and P17 (one version number cannot stand for two origins).
- Test scale: 101 test files; `pnpm typecheck`, `pnpm test` and `pnpm run build` are green.
