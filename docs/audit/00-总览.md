## 审计范围与四层架构

本项目为 **Electron 40 桌面应用**（DSH Launcher，版本 0.1.4），技术栈：
Electron 40 · electron-vite 2 · React 18 · Ant Design 6 · TypeScript 5 ·
sql.js (SQLite/WASM) · i18next · semver · electron-builder · vitest · pnpm。

源码规模：约 **105 个 TS/TSX 文件，约 1.5 万行**，分为四层：

| 层 | 目录 | 职责 | 备注 |
|---|---|---|---|
| 主进程-核心 | `src/main/core/` | 纯业务逻辑（profile、插件、market、dsh、home 等） | 测试覆盖较好 |
| 主进程-IPC | `src/main/ipc/` | 桥接核心逻辑与渲染进程 | 逐个通道注册 handler |
| 预加载层 | `src/preload/index.ts` | 通过 contextBridge 暴露受限 API | 约 117 处 ipcRenderer |
| 共享层 | `src/shared/` | `types.ts`(470行)、`api.ts`(236行) | 前后端契约 |
| 渲染层 | `src/renderer/` | React 视图/组件/自定义 hooks/i18n | 页面级文件偏大(715行) |

IPC 契约集中在 `src/shared/api.ts` 的 `WindowApi`，按业务分组为多租户命名空间：
`home / run / plugins / downloads / market / trash / settings / logs / window / store / dsh / data / app`，外加扁平 profile 相关通道约 20 个。

## 顶层结论（轮3 回填）

**总体判断**：分层与类型健康是亮点（core 纯净、shared 契约单一、几乎零 `any`、core 测试扎实、contextIsolation+无 nodeIntegration 基线正确、依赖无公开高危告警）。无崩溃级遗留、无"无需失陷渲染层即可利用"的高危项。

**三路各自的最高优先发现**：

| 维度 | 最高优先 | 级别 |
|---|---|---|
| 🔴 安全 | `profile:launch`（`ipc/profile.ts:424`）—— 代码库**唯一** shell 串拼接注入，`name` 未加引号可致 RCE（当前无渲染层调用方，但已经 preload 暴露） | P0 |
| 🍢 可维护 | IPC try/catch 样板 ×45+ 重复、渲染层重定义 shared 契约类型（漂移温床） | P0 |
| 🕰 遗留 | `core/types.ts` 争议（经裁决：**非死文件但可收敛**，见 05·X1）、`plugins.ts`/`dsh.ts` 上帝文件 | P1 |

**发展主线**：阶段0 安全止血（杀 `profile:launch`）→ 阶段1 样板收敛+契约对齐+死代码 → 阶段2 结构重构（拆 `plugins.ts`/`dsh.ts`+UI 三件套，测试守护）→ 阶段3 安全加固+渲染层测试 → 阶段4 文档运维。
