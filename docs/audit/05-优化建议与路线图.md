## 3. 执行注记（队长提示）

- **执行顺序纪律**：阶段0 → 1 → 2 应自上而下；每一阶段独立 commit，`pnpm test`+`typecheck` 双绿灯才进下一阶段。阶段2 结构重构**务必紧跟一次已测试通过的特性提交**做纯重构，便于二分回归。
- **需人工/授权项**：阶段4 的 `git push`、删远端分支需你本人操作或显式授权；S5.2 确认远端无人依赖旧分支。
- **能力面取舍（重要）**：安全线结论——本应用**核心防线是渲染层锁定**（CSP+README 净化+contextIsolation），当前基线有效；修复重点应放在"渲染层一旦失陷后的原语收敛"（阶段0+3.1/3.2），而非投入大量成本于低概率威胁。
- **遗留兼容红线（勿动）**：`DshEntry.versionDir`/`managed` 锚点、回收站实现、`migrateLegacyStore` 的**读兼容**（见遗留 2.2/2.3/2.1）。清理存量只做"删无调用方"，不做"删有意的兼容路径"。
- **契约变更纪律**（遗留 4.1）：合并期把"新增/修改 WindowApi 方法"当作需 review 的契约变更；先清掉 1.3 冗余 handler 再谈契约稳定。

## 4. 一句话总结

> **先杀 `profile:launch` 这颗唯一的 shell 注入雷（阶段0），再花小成本清掉所有复制粘贴型债务与契约漂移（阶段1），随后在测试守护下拆分两个上帝文件与 UI 三件套（阶段2），最后补纵深加固与渲染层测试（阶段3），并以文档与仓库运维收尾（阶段4）。** 无崩溃级遗留，无已公开高危依赖，基线健康；本项目的最大杠杆在\[阶段0→2\]的债务收敛，而非安全堆料。
